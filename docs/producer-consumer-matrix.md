# Producer and consumer matrix

Which object can be given to which decision-side consumer, by which route, and what is
refused. The rule behind every cell: **a consumer never infers a joint law, a posterior or a
causal response from a neighbouring object.** A mean is not an outcome distribution, a point
estimate is not a response, a posterior summary is not a prior signal, and a decision result is
not a source. Every route here is point-only; nothing on this page is an interval, a coverage
statement or a probability license.

The cells are `parity/producer_consumer.toml`, rendered between the markers below.
`python/tests/test_producer_consumer_matrix.py` reads that file and executes each
producer row as `test_producer_consumer_matrix_<row>_row`, parametrized over the
eight consumers.

The statistical carrier `inference.MeasuredInference` has its own original-source
producer and independent `load` consumer. It is not an additional decision
source: named scalar intervals and posterior parameter draws do not implicitly
become a scientifically bound outcome law or a `Contract.evaluate` source.
Its lifecycle and current-record requirements are documented in
[the lifecycle](lifecycle.md#measured-scalar-inference-and-independent-replay).

## Reading a cell

- **DIRECT**: a licensed entry point takes the producer (Python and Rust entry named).
- **ADAPTER**: a named step takes it: a different entry point, or a declaration the caller
  writes. An adapter can check original producer bytes and compatibility while still requiring explicit scientific declarations; its documented trust boundary applies.
- **REFUSED**: the consumer must not take it. The refusal code, detail and exception type are the ones the code emits.
  An incompatible input type is rejected as `CausalTypeError` before native evaluation.

A REFUSED cell is checked by feeding the producer to **every** entry point of the consumer and
requiring an exception, with the exact type where the consumer types its input
(`CausalTypeError`, `ScenarioDecisionRefusal`, `CompositionBundleRefusal`).

  estimate, a retargeted point, a posterior summary or a decision result.
- **Typed input and exporter boundaries.** `Contract.evaluate` accepts only an aligned joint
  artifact, a bound external claim or a mean source. `design.DesignDecision` requires a
  typed prior and action utilities. Bundle exporters must accept the declared `artifact_id`
  keyword; an incompatible signature raises `CausalTypeError` before invocation. Errors
  raised inside a valid callback propagate with their original type. Exported bytes still
  pass the Rust verifier for the requested bundle node kind.
- **Identity-only binding.** `design.DesignDecision(contract="<identity>", actions=...)`
  binds a contract by identity string only and does not check the action set against it; a
  `Contract` object does check it.
- **Checked original prior adapter.** `design.adapt_prior_to_signal` invokes the Rust adapter over original catalog posterior bytes; canonical ranking retains its sampled prior, source digests, transport declaration and observation-overlap checks. Numerical artifact replay does not independently authenticate source origin or caller-declared historical observation identities. See `test_prior_signal_bridge.py`.
- **Declarative plans and executed adapters differ.** `plan_recalculation` compares
  caller-supplied digests. Executing family sessions bind checked native state and
  measure actual work; the plan alone supplies no evidence that a fit or provider
  exists. See [recalculation capabilities](recalculation-capabilities.md).
- **Point-only producers use checked scientific mean adapters.** Measurement results,
  composed mechanism models, ledger synthesis outcomes, transported counterfactuals,
  observation claims and propagated means expose `as_mean_source(...)`. The canonical
  `results.MeanSource` is accepted by decision and inverse-query consumers. A producer
  carrying complete compatible coordinates may enter directly; otherwise the adapter
  requires explicit quantity, units, population, regime and selected functional or
  contrast. It retains values, identities, evidence and lineage. Standard errors,
  variance, laws and samples do not become joint decision uncertainty; quantile and
  probability criteria still refuse `decision_evaluation.mean_source_insufficient`.
  A ledger dependence envelope has no point. A transported probability is the mean
  of its binary indicator, requiring an explicit compatible functional declaration.
- **No bundle node, prior or sensitivity input for those producers.** Their artifacts are not
  composition-bundle node kinds (`detect_kind` is `None`), a point is not a `design.StatePrior`
  or a signal, and none is a `SensitivityArtifact`, a scenario stage or a failed contract; the
  cells are REFUSED with the typed errors the entry points raise. The `recalc_plan` cells are
  caller-declared digests, as for every producer. A bundle node kind, a sensitivity surface
  over a ledger dependence range, and propagation of a standard error into decision uncertainty remain unavailable.
- **A decision-reliability report is a diagnostic, not a source.** `decision_reliability.assess`
  returns three separate uncertainty components over a finite candidate set, all labelled
  uncalibrated. Its `decision` and `inverse_query` cells are ADAPTER cells: the caller declares
  the decided candidate's expected utility as a `MeanSource` or `MeanClaim`, with the draws
  digest as snapshot and the candidate-set digest as provider; the standard error, the ranking
  probabilities and the winner's-curse bound are not carried, and a quantile or probability
  contract is refused `decision_evaluation.mean_source_insufficient`. Its artifact is not a
  bundle node kind; publishing a ranking probability or interval refuses `cell_not_licensed`.
- **Mean-only native producers remain mean-only.** Actual producer-issued aligned credible
  rows are retained when present; handcrafted views cannot create them. A joint law from a
  native Python response needs draws retained there; Rust supplies one from credible draws.

## Observation-conditioned query claims

An `observation_query_claim` is the answer to one observation-conditioned query: a probability
given recorded values, its interventional counterpart, a posterior or an evidence requirement. A
probability is not a law. It reaches the decision consumer only through two `MeanSource`
coordinates the caller declares (the conditional probability and the interventional probability
of the same event, with the claim identity as provider), which answers an affine utility only; a
quantile or probability contract is refused `decision_evaluation.mean_source_insufficient`.
Conditioning and intervention are separate claims with separate identities and the matrix never
substitutes one for the other. The interval and calibration routes are closed
(`observation_query.interval_route_closed`,
`observation_query.calibrated_probability_closed`); see [observation-queries.md](observation-queries.md).

## Scientific bridge claims

The `scientific_bridge_claim` row is a point-only mean of one scientific quantity derived
from a claim about another under declared assumptions ([scientific-bridges.md](scientific-bridges.md)).
A mean-valued claim retains its target quantity and reaches `decision` and `inverse_query`
directly when the consumer's scientific coordinates match. `claim.as_mean_source()` exposes
the canonical `results.MeanSource` explicitly, preserving the point, evidence, identity and
lineage. This adds no law or uncertainty license: `BridgedClaim.require_value_kind` refuses
predictive laws, posteriors, identified sets and joint outcome laws with
`scientific_bridge.value_kind_substitution`; quantile and probability criteria refuse
`decision_evaluation.mean_source_insufficient`. The original source remains inspectable and
the bridged interval remains closed (`scientific_bridge.interval_not_licensed`).

## Fitted prediction boundary and the cohort-mean decision source

The matrix's `fitted_effect_model` row is the `CompactExport` representation (including
its support/mask declarations). The separate public `prediction.FittedEffectModel`
loads and verifies an executed parent analysis claim, then predicts CATE points from
its immutable fitted payload. Its `EffectPrediction` retains only point values and the
parent claim identity: it keeps no cohort snapshot, row identities, declared outcome
units or target-row support, and a bare prediction is not a `Contract.evaluate` source.
Prediction verification authenticates the parent model; it does not certify a new
cohort's support or create absolute potential-outcome means or a joint law.

The native cohort-mean contrast adapter closes that boundary for one operation. It
retains the verified fitted payload with the original query and contrast and the
producer's fitted-row support contract (a model without that contract is refused, not
assumed supported). It binds a cohort: strict named feature rows (none missing, none
extra), row identities, a cohort snapshot digest, a target population, finite
normalized weights and explicit outcome units. Every row is checked against the support
contract before anything is issued. It then issues one source-bound `mean_difference`
coordinate, the weighted mean of the conditional contrast, whose conditioning names the
cohort snapshot digest and whose parent claim, original diagnostics and assumptions are
preserved. The coordinate answers the expectation of an affine utility and nothing else.

| Request | Cohort-mean source |
| --- | --- |
| Expectation of an affine utility of the cohort-mean contrast | DIRECT: the one mean, point-only, no utility standard error or interval |
| Interval, band or posterior for the cohort mean | REFUSED: `cell_not_licensed`, `cohort_decision.interval_not_licensed` (route closed pending measured whole-method coverage) |
| Probability, quantile, tail expectation, nonlinear utility | REFUSED: `decision_contract_unsatisfied`, `cohort_decision.law_not_supplied` (needs aligned outcome draws from a producer of an interventional law) |
| Joint law with another quantity, or draws of the contrast | REFUSED: `joint_law_required`, `cohort_decision.joint_law_required` |
| Inverse query on the cohort-mean contrast | ADAPTER: the same mean as a finite-action forward source, point-only |
| Cohort from another population | ADAPTER under a declared covariate shift with every row inside the support contract; labelled `Extrapolative`; otherwise REFUSED `transport_missing_evidence`, `cohort_decision.shift_declaration_required` |

Trust follows the model's origin. A source built from a verified native analysis result
resolves as native: its numbers are recomputed from the retained payload and the cohort
rows, never read from a caller-supplied prediction. A source built from a caller-built
compact export is a declared model, resolves as an external attestation and is refused
where native is required. The export (`cohort_decision_source_v1`) embeds the model
payload, the cohort rows and the result; a consumer holding only the bytes and the
retained identity recomputes every number and refuses a changed row, weight,
coefficient, unit, population or parent, including a resealed container.

For a linear compact model that retains its coefficient covariance, the variance of
the weighted cohort-mean contrast `phibar' V phibar` is computable. It is reported as
an uncalibrated standard error on the source and is never passed to a decision input.
Its calibration is a whole-method design (cohort-weight and support-selection step
included) that has not been measured, so the interval route stays closed.
