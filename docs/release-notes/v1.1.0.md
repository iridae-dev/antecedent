# Antecedent 1.1.0

The first compatible minor after the 1.0 contract freeze. 1.1 strengthens the
evidence and prepared-execution behavior of families that were already
licensed: it adds known-truth graph-mixture effects, freezes the PAG and ADMG
numbers, and makes `prepare()` cache identification for envelopes and graph
posteriors. No query kind, graph semantics, identification theory, support
cell, or artifact format changes in this release. The public Python surface
gains only additive entry points for supplying a constructed graph posterior
(listed below); the 49 frozen root names are unchanged. Workspace and Python
package versions are **1.1.0**.

## Known-truth graph mixtures

`conformance/bayesian/known_truth_mixtures` replaces the graph-posterior
families' prepared-vs-fresh smoke evidence with analytic data-generating
processes consumed through the staged path.

For static `AverageEffect`, two identified DAG atoms have frozen empirical
effects 3 and 2 at posterior weights 0.5 and 0.3. A valid reverse-causal
`Y -> T` atom has weight 0.2 and no admissible backdoor identification. The
envelope therefore pins `E[tau | identified] = 2.625` while
retaining `unidentified_mass = 0.2`; the Bayesian prior does not turn the
unidentified atom into identified mass. The same test exercises `none`, `cheap`,
and `full`, retaining the validation-specific assertions in addition to the
effect pin.

For DBN-posterior `PulseEffect` and single-step `SustainedEffect`, the frozen
law is `defect_t = 0.9 * pressure_(t-1)`. A lag-one atom with weight 0.7 pins
the effect at 0.9. A second valid atom adds
`pressure_(t-1) -> pressure_t`; its stationary autoregressive ancestry reaches
the finite-history certification boundary, so its 0.3 weight remains
unidentified. Both tests compare fresh and prepared execution, but that
equality is now an extra invariant rather than the licensed evidence itself.

## Numeric PAG and ADMG evidence

`conformance/estimate/pag_ate_envelope` freezes the full input contingency
table for a three-completion PAG. The completion effects are 0.40, 0.52, and
0.40, so the Frequentist mass-weighted estimate is 0.44. The seeded conjugate
Bayesian envelope is separately pinned at 0.44161301501541206. Executing tests
cover explicit and accepted PAGs under every licensed inference and validation
coordinate.

`conformance/estimate/admg_frontdoor_functional` freezes a binary front-door
law on `T -> M -> Y` with `T <-> Y`. The empirical front-door functional is
0.3, pinned for explicit and accepted ADMGs under all three licensed
Frequentist validation levels. The pre-existing generalized-adjustment and
general-ID fixtures continue to pin identification; these new fixtures add
the number returned after identification.

## Prepared identification is actually prepared

`PreparedStudy` now retains the identification product each envelope executor
needs:

- PAG preparation stores the generalized-adjustment completion envelope and
  its aggregate identification result.
- Bidirected ADMG preparation stores the general-ID result and selected
  functional estimand.
- Static graph-posterior preparation stores the original weighted atom set,
  identified/unidentified flags, and each identified atom's result and
  estimand.
- DBN-posterior preparation stores the corresponding temporal result,
  estimand, and finite-unfolding indexer for every identified atom.

DBN atoms are cached under a position-derived internal identity rather than
the public contemporaneous-mask key. This keeps lag-distinct atoms from
colliding, and preserves the correct weight when an atom is demoted after a
fit failure, regardless of posterior order. The public `GraphPosterior`
representation is unchanged.

Estimate and same-schema refresh clicks reuse those frozen products and emit
`exec.identify.cached`. A fresh one-shot run still identifies and does not emit
that diagnostic. Graph and query identity remain immutable on a prepared
handle; changing either requires a new prepare cycle, which identifies the new
coordinate rather than reusing a stale cache. Unidentified posterior atoms
remain unidentified in both paths.

Reuse is verified, not merely flagged: progress sinks receive an
`identify.compute` label exactly when identification is computed (fresh runs,
`prepare`, and the sharp-RD click). The Rust suites record that label and
assert it never fires on a prepared estimate or same-schema refresh click for
the single-graph, PAG, bidirected-ADMG, static graph-posterior, and
DBN-posterior paths. Bayesian PAG results now carry the same
`identify.pag.envelope` completion-mass diagnostic as the Frequentist arm.

## Supplying a graph posterior from Python

`antecedent.discovery.GraphPosterior.from_atoms(names, weights, adjacency, ...)`
builds a posterior from explicit atoms, and `analyze(discovery=...)` and
`PreparedAnalysis.prepare(discovery=...)` accept a constructed
`GraphPosterior` (including one returned by a discovery engine's `run`). The
handle exposes `lag_masks` and `algorithm`. These are additive entry points
under the existing `GraphPosterior` name; no frozen root or stage-module name
changes.

The supplied-posterior path fails closed. A posterior is bound to the data
schema, so a reordered or differently sized table is refused. `from_atoms`
rejects non-DAG or out-of-range masks, unnormalized weights, and lag masks
without `max_lag`. A replayed posterior keeps its producer's algorithm tag and
convergence verdict. `analyze` refuses the options this path cannot honour
(`identifier=`, `estimator=`, `estimator_config=`, `validators=`,
`population_registry=`, `return_posterior_artifact=`, and Bayesian prior
transfer or mapping) rather than dropping them, and a DBN posterior paired
with a static `AverageEffect` is refused.

## Compatibility boundary

The licensed set remains 77 cells of 1406 meaningful coordinates. This release
changes the evidence recorded on existing rows and the performance semantics
of their prepared path; it does not add a cell or weaken a refusal. Artifact
format 0.4 and the 1.0 public API freeze are unchanged.

## Explicit refusals

The [support matrix](../support-matrix.md) is authoritative; omission from the
licensed block below means refusal unless the coordinate is one of the matrix's
typed n/a rules. 1.1.0 changes no refusal:

- `Counterfactual`, static `MediationEffect`, `AverageDerivative`,
  `PointDerivative`, `Elasticity`, `SemiElasticity`, `DirectionalDerivative`,
  and `ResponseJacobian` have no licensed analysis cell. They remain importable
  so callers get a typed refusal rather than an absent API.
- `Cpdag` has no licensed analysis cell. Incomplete `TemporalCpdag` and
  `TemporalPag` analysis is likewise refused; completing one to a
  `TemporalDag` is a different coordinate.
- Bayesian response curves/intervention responses, response mixtures over
  graph posteriors, Frequentist graph-posterior analysis, and non-DAG posterior
  atoms (`Admg`, `Cpdag`, or `Pag`) are refused. `TemporalDag` DBN-posterior
  pulse/single-step-sustained validation-`none` cells are the documented
  temporal exception.
- Accepted or graph-posterior path-specific and interventional-distribution
  analysis is refused; their only licensed cells are explicit-DAG,
  Frequentist, validation-`none`.
- Bayesian temporal mediation and temporal-mediation cheap/full validation are
  refused. Multi-step sustained windows remain estimator-refused; the licensed
  sustained form is single-step.

A licensed cell still means the recorded staged behavior and evidence contract
hold. It does not verify the cell's causal assumptions from observed data, and
it does not establish universal Frequentist or Bayesian calibration.
