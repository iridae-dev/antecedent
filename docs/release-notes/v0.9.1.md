# Antecedent 0.9.1

A patch on 0.9.0. 0.9.0's limitations were honest, but several licensed rows
named a capability the code did not actually run. This cut implements what
those rows already say rather than demoting the axis. No new query kinds, no
new identification theories, and no cells added to or removed from the matrix.
Workspace and Python package versions are **0.9.1**.

## Bayesian validation on multi-graph envelopes

`execute_pag_bayesian` and the graph-posterior ATE path used to record a
`refute.bayesian.ppc.skipped` diagnostic and run only the effect refuters on
the mixture mean. Both now run prior and posterior predictive checks per
identified completion and aggregate them by graph-posterior mass, recording
`refute.bayesian.ppc.envelope`. Under `full` they additionally run
prior-sensitivity per completion and mix the summaries.

Mixture aggregation uses the law of total variance for predictive dispersion:
the reported `predictive_sd` is the SD of the mixture predictive distribution,
so disagreement *between* completions widens the envelope rather than being
averaged away. Prior-sensitivity summaries are mixed the same way. Location and
tail probabilities remain weighted means.

This is a mixture-weighted aggregate of per-atom checks, not a joint predictive
check over the graph posterior, and the fixtures still pin identification
rather than the PPC numbers.

## Temporal uncertainty is one contract

`TemporalResponseEstimator` previously hardcoded zero bootstrap replicates
while the Pulse/Sustained path carried the `Study`'s configured
`bootstrap_replicates`, so the two disagreed on standard errors even where
point estimates matched. Pulse, single-step Sustained, and the dose × horizon
surface now share the `Study` bootstrap contract: with positive replicates the
surface's pointwise SEs are the bootstrap SD of the g-computed level, and with
zero replicates they remain the analytic OLS linear-functional SE. Bootstrap
replicates are a core `Study` knob; the Python `analyze()` response surface is
analytic (`analyze()` does not expose `bootstrap=` for response queries), so it
returns the zero-replicate SE and matches the frozen conformance surface.

Every horizon resamples the same rows, so pointwise SEs stay comparable when
the surface is read across horizons. Failure accounting matches the rest of the
crate: too few surviving resamples, or a soft-failure fraction over the
crate-wide threshold, means the analytic SE is used instead — and the response
carries an `estimate.temporal_response.bootstrap_degraded` warning saying so,
rather than presenting an analytic SE as a bootstrap SE.

## Bayesian panel repeated measures

Bayesian panel g-computation entered repeated measures on the same unit into
the likelihood as independent rows, which understated the posterior. The panel
path now passes unit ids through to a compound-symmetry random-intercept GLS
whitening of the coefficient fit, with method-of-moments variance components.
G-computation still uses the original design matrix; only the coefficient
likelihood is whitened. Mismatched unit ids fail closed.

The whitening declines (and the fit falls back to stacked) when the ids are
unusable: fewer than two units, all-singleton units, or non-finite variance
components. `conformance/estimate/panel_hierarchical_vs_stacked` pins the
direction and a magnitude floor on a seeded DGP, not a known-truth SD.

## Evidence that executes

Licensed `ResponseCurve` runs with `ObservationSpec != Complete` now consume
`conformance/response/observation_primitives` from an executing test, and
`scripts/gate_evidence_reachability.sh` fails if a licensed cell names that
fixture without a test function that both loads it and constructs a
non-`Complete` `ObservationSpec`.

`scripts/gate_calibration.sh` gained nominal-90% interval coverage cases for
Bayesian Pulse, Bayesian single-step Sustained, and hierarchical Bayesian panel
intervals on known DGPs. These run weekly, not on every PR.

## Explicit refusals

The [support matrix](../support-matrix.md) is authoritative; omission from the
licensed block below means refusal unless the coordinate is one of the matrix's
typed n/a rules. 0.9.1 changes no refusal — the boundary is exactly 0.9.0's:

- `Counterfactual`, static `MediationEffect`, `AverageDerivative`,
  `PointDerivative`, `Elasticity`, `SemiElasticity`, `DirectionalDerivative`,
  and `ResponseJacobian` have no licensed analysis cell. They remain importable
  so callers get a typed refusal rather than an absent API.
- `Cpdag` has no licensed analysis cell. Incomplete `TemporalCpdag` and
  `TemporalPag` analysis is likewise refused; completing one to a
  `TemporalDag` is a different coordinate.
- Bayesian response curves/intervention responses, response mixtures over
  graph posteriors, Frequentist graph-posterior analysis, and non-DAG posterior
  atoms (`Admg`, `Cpdag`, or `Pag`) are refused. `TemporalDag` DBN-posterior
  pulse/single-step-sustained validation-`none` cells are the documented
  temporal exception.
- Accepted or graph-posterior path-specific and interventional-distribution
  analysis is refused; their only licensed cells are explicit-DAG,
  Frequentist, validation-`none`.
- Bayesian temporal mediation and temporal-mediation cheap/full validation are
  refused. Multi-step sustained windows remain estimator-refused; the licensed
  sustained form is single-step.

A licensed cell still means the recorded staged behavior and evidence contract
hold. It does not verify the cell's causal assumptions from the observed data,
and it does not establish universal frequentist or Bayesian calibration.
