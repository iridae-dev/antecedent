Antecedent is a compiler and runtime for causal science. Version 3.0 lets you model systems with feedback, evaluate and search coordinated intervention programs, connect experimental evidence to decisions and to the next study, and prepare, branch, reuse and embed an analysis without refitting what did not change. A result is still a claim: it carries its identification, support, uncertainty and calibration status, and successful execution does not upgrade a scientific claim.

Each section below names the task, the public route, and what remains a boundary. The generated inventory further down lists every new cell with its exact claim and the refusals it keeps.

## Model feedback and dynamic systems

You can now ask what happens when one component of a system with feedback is observed, clamped or shocked, using the cyclic routes (`antecedent.cyclic`, `Study::prepare_cyclic`). The answer is a model-conditional response: it holds for the specified or fitted equations and their declared equilibrium and selection assumptions. An intervention that has no solution is retained as failed mass rather than dropped. See [cyclic systems](../guides/cyclic-systems.md).

- Prepared cyclic handles compile a typed program without fitting, sampling or encoding an artifact. Changing only the response worlds reuses a compatible fit; changing observations, mechanism parameters, priors or fitting policy refits.
- Nonlinear fitting, held-out joint interventions, within-system counterfactuals and fresh-process replay are covered by the cyclic example and its checks.

## Evaluate and search joint intervention programs

You can now evaluate a coordinated intervention program over a horizon against a baseline and read one joint uncertainty from the shared fit, using `InterventionContrast::linear` and the joint-response routes. The result retains the declared history, time frame, population and outcome of every world. Adding a term to a contrast changes the question; it does not identify the added world. See [joint intervention responses](../guides/joint-intervention-responses.md).

- Joint draws keep their alignment, so contrasts and weighted time-window targets use one covariance rather than combined marginal intervals.
- Search certificates are scoped to an explicitly enumerated finite domain. Continuous search reports a best-found feasible point.
- Frequentist local Gaussian and cluster-sandwich realizations are approximations, not posterior draws, and Bayesian laws must pass their convergence checks.

## Connect evidence, decisions and further studies

You can now carry a retained response law into experimental evidence through an explicit estimand mapping, update a decision, and rank further studies by information value and cost. A decision is bound to its evidence: withdrawing or superseding a source invalidates current decision use, while historical replay of the numbers stays available and never renews withdrawn permission. See [the experiment to next study tutorial](../tutorials/experiment-to-next-study.md), [replay and current decisions](../tutorials/replay-and-current-decisions.md) and the [evidence ledger](../evidence-ledger.md).

- `FlagshipWorkflow::decision()` returns a result; `DecisionAuthority::withdraw_source` records trust loss, and decision export is a version 2 envelope that needs the caller's current authority to load.
- Overlap between a study and a prior is decided from the evidence ledger. An undecidable lineage refuses rather than counting as disjoint.

## Prepare, branch, reuse and embed

You can now prepare an analysis once, branch it onto new observations or new declarations, and execute each branch without disturbing earlier results. Prepared studies are immutable; `ant.rebind` changes observations, `ant.reconfigure` changes declarations, and `branch.reuse` reports what was retained and invalidated. Every execution returns an `Outcome`: a scientific refusal is a returned value with a reason code and next action, while invalid arguments and operational failures raise.

- `ant.Execution` carries seed, threads, cancellation, resource limits and observers; `ant.Frequentist` and `ant.Bayesian` carry statistical budgets and profiles.
- `ant.estimation.prepare_many` fits a compatible family once and returns selectable member outcomes with their family inference.
- `.export()` returns a typed artifact with an `expectation`; `ant.load` runs the format's independent consumer and returns a read model with no live study. Loading is not a live study.
- Rust compiles the retained scientific program once; allocation is admitted under caller policy and reported as quotes, not process memory.

## How to read the claims

| Term | Meaning |
| --- | --- |
| `point_only` | An exact or plug-in point estimate. No interval of any kind is claimed. |
| `nominal` | An interval whose coverage was never measured at its own coordinate (`estimator_grid_not_measured`). Cells publish none. |
| `calibrated` | An interval with a coverage record measured at its own coordinate; shown to readers as a *statistical interval*. A cell is described this way only once its records exist. |
| `structural_envelope` | The range of an answer over explicitly supplied structural scenarios. Not a confidence interval. |
| `assumption_range` | The range of an answer over a declared sensitivity set. Not a confidence interval. |
| `none` | No numerical claim: identification or inspection only. |
| statistical interval | The reader-facing name of a `calibrated` interval; it appears only beside a measured coverage record. |

Calibration for 3.0 is unmeasured until the release measurement phase. Read `result.inspect().calibration` for the standing of each result.
