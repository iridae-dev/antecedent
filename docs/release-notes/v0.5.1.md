# Antecedent 0.5.1

0.5.0 shipped continuous causal responses. 0.5.1 makes the claim→evidence
chain machine-checkable and corrects wording that had outrun evidence. No
estimator semantics changed except one refusal.

## Per-row response diagnostics, with a contract

`analyze(..., response_options={"export_row_diagnostics": True})` exports three
aligned channels from the continuous-response estimator: retained-row indices,
cross-fitted Kennedy pseudo-outcomes, and grid-major local-WLS influences.
Exported diagnostics are scientific objects users will compute on, so their
contract is stated exactly in
[causal-responses.md](../causal-responses.md#row-diagnostic-export-contract):
what an influence value is mathematically (and what it is **not** — the
semiparametric efficient influence function), the zero-sum centering identity,
the bit-for-bit reconstruction of both reported bands, layout and row-index
semantics, fold behavior, and what is stable versus construction-dependent.

## Evidence became machine-readable

Every `done` capability row in the parity manifests now carries
`evidence_kind` — one of `implementation_exists`, `internal_known_truth`,
`internal_cross_check`, `frozen_external_oracle`, `behavioral_parity`,
`contract_equivalence` — plus `external_oracle`, `known_truth_fixture`, and
`limitations` where they apply. The schema gate enforces the
fixture-authoritative rule: a row may not name an upstream oracle its frozen
fixture does not record.

Classifying all 168 rows corrected the record in both directions. Most
notably: the estimate conformance suite asserts against each fixture's
synthetic `true_effect`, not the recorded DoWhy estimate, so those rows now
say `internal_known_truth` with explicit limitations; the genuinely external
comparisons (`estimate.linear_regression` vs DoWhy at StableFloat,
`estimate.conditional` vs statsmodels at 2e-9, the Tigramite/causal-learn/
lingam/statsmodels discovery matrices, bpbounds, and the causaleffect
transport subset) are named as such.

## Three new standing gates

- **Metadata consistency** — package version, artifact format, retired
  identifiers, provenance ids and DOI syntax, and oracle-ledger/fixture
  agreement are checked on every PR. One canonical source per fact.
- **Evidence reachability** — a conformance fixture is either loaded by an
  executing test or declared recorded-but-unexercised in a shrink-only
  ledger; an unexercised fixture cannot back a closed oracle row or an
  unmarked citation. The gate's own dry run found two fixtures cited as
  evidence that no test loaded.
- **Implementation deviations** — new provenance records must state how the
  implementation departs from the cited construction (`= []` is an explicit
  assertion of exact reproduction). The 139 pre-existing records are frozen
  in a backlog that can only shrink. First records corrected: `estimate.aipw`
  (no cross-fitting — the DML paper's rate conditions are not inherited) and
  `estimate.response.kennedy_dr` (restricted nuisance families, Gaussian
  plug-in treatment density, Silverman default bandwidth, deterministic
  folds).

## Corrections

- Python builds always compile the native extension with Cargo's release
  profile (`[tool.maturin] profile = "release"`). A stale editable install
  could previously be rebuilt in the debug profile without any signal —
  identical numbers, ~50× the wall time. A debug-profile extension now
  announces itself with a `RuntimeWarning` on import
  (`antecedent._native.__build_optimized__`).
- Unconverged Huber IRLS is refused instead of published with an analytic SE.
- The artifact-migration conformance test now checks the live `STABLE_FORMAT`
  (0.3) instead of a stale hardcoded copy.
- 14 oracle-ledger rows no longer imply external-package agreement their
  fixtures never recorded; 9 stale `pending-generation` pins now carry the
  real pins.
- The three recorded DoWhy general-ID oracles are marked recorded-but-
  unexercised everywhere they are cited, matching their own fixture notes.
- All 40 rustdoc warnings fixed; public error docs no longer point at
  private items.
- Zenodo archiving reads a dedicated `.zenodo.json`; `CITATION.cff` is now
  schema-valid CFF 1.2.0 (Zenodo accepts neither valid spelling of the dual
  license, so each consumer gets the file it can parse).
