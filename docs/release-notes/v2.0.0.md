# Antecedent 2.0.0 — draft release notes

> **Release preparation only.** Workspace and Python package metadata remain
> at 1.11.0 until the release cut. This document is the active documentation
> target and is not a published release announcement.

## Cohesive workflow

Antecedent 2.0 keeps the established lifecycle—identify, estimate, inspect,
refresh, export, and consume—across static, temporal, response, Bayesian,
discovery, validation, attribution, design, state, and artifact work. Results
continue to retain the causal contract rather than exposing an estimate alone.

## What 2.0 adds

- Rust-native learner contracts and fold-local nuisance fitting for DML,
  DR-Learner, and honest causal-forest routes, with held-out diagnostics,
  overlap handling, provenance, and portable prediction where supported.
- Structural transport requests with explicit populations, evidence catalogs,
  sampling and regime information, typed identification outcomes, and durable
  derivations. A missing joint or evaluator is reported distinctly from a
  theorem-stage refusal.
- Population-aware expression evaluation and durable evidence/derivation
  records without replacing existing causal APIs.

## Support and calibration

The [support matrix](../support-matrix.md) remains authoritative. An inventory
entry or implemented type is not a license for every query, graph,
identification, inference, and validation combination.

The long-running calibration measurement and attestation have not been run for
this preparation release. Existing records retain their stated scope; 2.0 does
not relabel them as new evidence. Intervals expose calibration status and
reasoning in the result contract: `calibrated` requires a record that still
attests the current code, so drifted records are not reported as calibrated.

## Explicit refusals

Every root query in the matrix has at least one licensed cell, so no query
family is refused as a whole. Individual combinations refuse for graph,
structure, evidence, inference, validation, support, or budget reasons; a
combination that is not listed in the licensed block below is refused. See the [support matrix](../support-matrix.md#refusal-reasons)
for the complete coordinate-level boundary.
