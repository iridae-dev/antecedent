# Antecedent 2.2.0

Antecedent 2.2.0 makes more questions executable while keeping the scope of each answer visible. You can ask which **enumerated interventions** reach a target mean, compare many related claims with their shared score covariance, and diagnose why an analysis cannot support the answer you requested. The release also expands bounded transport, counterfactual, and study-planning routes. Each result retains its assumptions, support, provenance, and refusal reason.

### Start with the question

| If you need to… | Start here | What you get |
| --- | --- | --- |
| Ask “what would have to be true for this outcome?” over interventions you name | [Finite-action inverse outcome](../guides/inverse-outcome.md) | Feasible, infeasible, unsupported, and unevaluated actions relative to a licensed forward mean response and the enumerated grid |
| Keep a large AIPW analysis on the score-table path | [Penalized propensity](../guides/penalized-aipw.md) | Declared ridge or lasso propensity, cross-fitted scores, overlap diagnostics, and retargeting |
| Compare contract-specific routes or other related claims | [Configured batches and retargeting](../guides/batch-retarget.md) | Joint plug-in covariance and named contrasts on a shared row snapshot |
| Work with repeated entities or dyads | [Clustered cross-fitted AIPW](../guides/clustered-dml.md) | Cluster-owned folds, score table, and dependence-aware standard error |
| Declare a composite treatment | [Joint cells and derived treatments](../guides/joint-cells.md) | Checked source roles, cell overlap, and a factorized propensity |
| Analyze matched case-control samples | [Matched case-control odds ratio](../guides/matched-case-control.md) | A conditional odds ratio with design-specific refusals for absolute risks |

The inverse query is a **finite search over already evaluated forward points**. It does not infer an unobserved scenario from an outcome, interpolate missing doses, or turn point estimates into probabilities. A feasible action is feasible under the stated forward assumptions and target threshold; an action outside empirical support stays unsupported. The report binds the forward claim, program, and data snapshot identifiers when supplied. Its `verify()` method replays the local classification; it is not an authenticity check for the forward model.

For exploration before estimation, [dependency preflight, cost estimates, and overlap diagnostics](../guides/preflight-diagnostics.md) make failure modes actionable. For structural questions, the bounded [transport and study planning routes](../guides/transport-scope.md) say which inputs identify a target and what hypothetical evidence could repair a failed search.

**Inference boundary before the final calibration pass.** Point estimates, plug-in score covariances, structural envelopes, and assumption ranges have the meanings stated below. New sampling intervals whose coverage records have not been measured at their exact coordinates are withheld as release claims, even when an implementation can calculate a candidate band. Final calibration and support-matrix reconciliation are the remaining release-cut work.

## How to read the claims

| Term | Meaning |
| --- | --- |
| `point_only` | An exact or plug-in point estimate. No interval of any kind is claimed. |
| `nominal` | An interval whose coverage was never measured at its own coordinate (`estimator_grid_not_measured`). 2.2 cells publish none. |
| `calibrated` | An interval with a coverage record measured at its own coordinate; shown to readers as a *statistical interval*. A cell is described this way only once its records exist. |
| `structural_envelope` | The range of an answer over explicitly supplied structural scenarios. Not a confidence interval. |
| `assumption_range` | The range of an answer over a declared sensitivity set. Not a confidence interval. |
| `none` | No numerical claim: identification or inspection only. |
| statistical interval | The reader-facing name of a `calibrated` interval; it appears only beside a measured coverage record. |

## Corrections to 2.1

- The one-factor `z_transport_mechanism_sensitivity` refuses a source law whose shared parent marginal does not have unit mass within 1e-10, as `ZTransportSensitivityError::IncompleteKernel` (its existing reason codes are unchanged). It weighted strata by the law's raw parent mass, so a law accepted under a loose `LawTolerance` (total mass 0.8, say) returned a baseline and range scaled by that mass. The joint route already enforced unit mass.
- Discovery block-bootstrap stability checks (`BlockBootstrapStability`, `OrientationStability`, `RegimeStability`) no longer let block-junction gap rows into CI tests under a partial CI `mask_type`: on data with no missing or masked rows the replicates run under the full `yxz` mask, which is equivalent there; on data with missing or masked rows a partial mask is refused as `NotApplicable`. The Python bindings always used `yxz` and are unchanged.
- The design ranker's graph-entropy score (`ReduceGraphEntropy`) is now monotone in the design amount: its observation channel is the reliability-weighted mixture of a perfect and a uniform report, so zero reliability carries no information and small designs no longer outrank larger ones (a one-sample increase now scores about 0 instead of 0.31 nats). Entropy scores and rankings change accordingly; the `conformance/design/expected_information_gain` oracle is regenerated against dit 2.3.
- Clustered, multiway and HAC standard errors for propensity and covariate-distance matching remain refused (`estimator_inference_mismatch`): fixed-match nearest-neighbour matching has no clustered influence function (the Abadie–Imbens martingale representation is proved for random samples only, and neither the bootstrap nor the Otsu–Rai wild bootstrap covers clustered or serially dependent data). The reasoning is now documented and the refusal is pinned for every dependence-robust SE kind in Rust and Python; its message now recommends AIPW rather than propensity weighting, which has no cluster standard error.
- Refusals can now name a remedy in a structured, optional field: `EstimationError::remedy()` / `CausalError::remedy()` in Rust and `err.remedy` on every Python `CausalError` (`None` when absent). The additive-GAM non-convergence and the plug-in Jacobian / directional-derivative "at most two treatments" refusals now say what to change. Messages, exception classes and reason codes are unchanged.
- Every conformance fixture cited as known truth now records where its truth comes from (`oracle.kind`), and the evidence-reachability gate fails if a cited fixture has none.
- The Python workflow guide now documents counterfactual per-unit intervals and support flags, the pointwise DR-Learner CATE route, and batch inference with `analyze_many` (shared seed, max-t simultaneous intervals, BH/BY-adjusted p-values).
- Frequentist counterfactual unit effects still publish no per-unit interval (`unit_effect_intervals` is `None`); the `gcm.counterfactual.uncertainty_unavailable` diagnostic, API docs and support matrix now say why (a unit ITE is not identified, depends jointly on every fitted path mechanism and on disturbances recovered with the same parameters, and mechanism families are chosen on the same data). Use `inference=Bayesian` for calibrated per-unit `unit_posterior_quantile` intervals, or `DrLearner::fit_pointwise_profiles` for an uncalibrated pointwise interval on tau(x).
- Riesz sensitivity now centres its worst-case interval on the published estimate it reports under, not on the diagnostic fit's clipped IPW estimate; the tipping δ and the bound endpoint now describe the published effect.
- Silverman's normal-reference bandwidth is one shared rule in `antecedent-stats`, (4/((d+2)n))^(1/(d+4)) per standardized coordinate. The univariate default used by response kernels and do-samplers drops the rounded constant 1.06 for the exact (4/3)^(1/5), so default bandwidths are 0.074% narrower; nonparametric sensitivity is unchanged.
- Transport grids distinguish missing evidence from a support failure: `SupportStatus` gains `missing_evidence` (Rust `SupportStatus::MissingEvidence`, additive on the wire), the weakest support label. A grid point with no supplied law, provider or declared domain reports it; an empty stratum or zero denominator stays `outside_empirical_support`. Grid points carry `support_status`, and the grid support slot counts the two separately. Earlier grid artifacts still load. Rust code matching `SupportStatus` exhaustively needs a new arm; grids with unavailable points get a new execution identity.
- Transport bindings report one identification-status vocabulary, `identification_status` ∈ {`identified`, `proven_non_transportable`, `missing_evidence`, `not_certified`, `budget_cancel`}: `identification_status()` on every Rust transport decision type, and the `identification_status` property or key on Python stages, decisions, scenario rows, study-plan arrivals and `ant.identify` certificates. Earlier spellings (`exhausted`, `stopped`, `unevaluated`, `structurally_unidentified`, `combined_identified`, `named_route`) remain in `outcome`/`status` and are deprecated; `antecedent.transport.advanced.identification_status()` and `TransportOutcomeKind::from_identification_status` read them. Reason codes are unchanged.
- Sequential priors hydrated from a posterior artifact now carry the full coefficient covariance (dense `V0`, `PriorSpec::CoefficientCorrelation`), so sequential updating no longer understates uncertainty against pooling; conjugate known-σ² updating reproduces the pooled posterior. Summary-only artifacts and effect-functional or named-parameter mappings stay diagonal.
- Known-σ² Gaussian posteriors record their σ² as a constant `residual_variance` quantity, and prior hydration converts with it instead of the target's residual-variance estimate; artifacts written earlier keep the disclosed plug-in.
- Frequentist `ConditionalEffect` still fits one modifier, because its calibrated interval covers only that coordinate. Asked for several, its refusal keeps the same message and reason code and now carries a `remedy` naming the routes that take a modifier set: the Bayesian conditional estimator (`EstimatorId::BayesianConditional`) and `antecedent.handoff.econml(result, modifiers=[...])`. In Python, passing a sequence as `ConditionalEffect(modifier=...)` now raises `CausalUnsupportedError` with that remedy instead of a later type error.
- Batch estimation (`analyze_many`, `BatchStudy::estimate_many`, `PreparedBatch.prepare` / `estimate`) fits each identical cross-fitted AIPW propensity or outcome model once for the whole batch, reusing a fit only when rows, treatment coding, adjustment design, fold plan and learner options are bit-identical, so every result matches its per-query fit exactly; `batch.shared_design` reports `shares_propensity` / `shares_outcome_residualization` per result.
