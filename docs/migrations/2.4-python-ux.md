# Python API migration for 2.4

Antecedent 2.4 connects notebook exploration to durable scientific systems through specialized objects with shared inspection and persistence conventions. Rust still validates scientific claims, performs numerical calculations, establishes identities, and grants licenses.

## Replace common 2.3 expressions

| Earlier expression / pattern | 2.4 replacement | Why |
| --- | --- | --- |
| `exported = obj.export(); exported.artifact` | `data = obj.export()` | Export returns bytes. |
| Need bytes and a producer expectation | `envelope = obj.artifact(); envelope.data; envelope.expectation` | Retain expected identity independently. |
| `loaded.artifact.payload` | `loaded.decoded_artifact.payload` | `artifact()` now creates an export envelope. |
| Mutate a report mapping directly | `editable = report.to_dict()` | Scientific read models are immutable. |
| `identification.validate(data)` | `identification.estimate(data, refute="cheap")` or `result.refute(...)` | Validation attaches to a concrete execution. |
| Refresh with changed assignments or IDs | `new_study = study.reprepare(new_data)` | A scientific design change needs new preparation. |
| Pass an execution into another callback session | `execution.export()` then explicit `session.resume(...)` | Executions belong to their producing session. |

Before, receipt-oriented code extracted a nested artifact. Now save bytes directly:

```python
# 2.4: result is an already estimated execution.
data = result.export()
envelope = result.artifact()
expected_record = envelope.expectation.to_dict()
```

Before, code edited a returned dictionary in place. Now edit an independent copy:

```python
report = result.inspect()
editable = report.to_dict()
editable["application_note"] = "Reviewed by the analysis owner"
```

These are continuation snippets, not standalone analyses. For executable setup, validation, refresh, composition and independent consumption, run [the notebook-to-system tutorial](../guides/notebook-to-system.md).

## Retained studies and executions

Prepare with `ant.prepare(data, query=..., graph=...)`. Review `study.identification` and `study.inspect_plan()` before fitting. Identification is retained from native preparation; reading it performs no fitting or repeated search. Graphless designs describe their design-based identification explicitly.

`study.last_result` is `None` before execution. After a successful estimate or refresh, `study.inspect()` shows the execution and reports `stage="executed"`. `inspect_plan()` continues to describe preparation. A failed operation preserves the preceding study and successful result. Replacing a snapshot without execution invalidates the latest execution view.

Named assignment and design-ID columns are frozen at preparation. Supplying changed values or a changed row order to estimation, refresh, or refutation raises a structured error naming the column. Omit design columns to update observations under the same design, or call `study.reprepare(new_data)` to resolve the original named declarations against a new table. `query=` replaces the declaration. Repreparation returns a new study and repeats scientific checks.

`result.refute(suite="cheap")` validates that result's immutable execution snapshot, including after its study has been refreshed. `study.refute(suite="cheap")` validates its latest successful execution. Optional supplied data must match that execution. To validate different observations, refresh and estimate them first.

`Identification.validate(data)` is removed. Use `identification.estimate(data, refute="cheap")` for combined estimation and validation, or `result.refute(...)` afterward.

## Immutable scientific read models

Scientific reports, certificates, receipts, consumed bundles and exposed arrays are detached from caller inputs and recursively protected. Sequences are tuples and mappings are read-only. Use `to_dict()` for an independent JSON-safe editable copy. Repeated reports provide `to_rows()`; `inspect()` retains family-specific details and concise notebook representations.

Adaptive inference exposes method-specific `result.payload` records instead of positional `values`. Posterior arms, weighting estimates, confidence-sequence readings and sequential looks have named fields. An absent stopping event is `None`. Reliability reports expose typed immutable records; raw native layouts remain internal.

Integer inputs use lossless normalization. Python/NumPy integers and exactly integral finite floats are accepted within native bounds. Boolean count values, fractions, non-finite values and out-of-range integers are refused with field and element locations. Scientifically declared Boolean assignment encodings remain supported.

Both `import antecedent as ant` and explicit module imports expose statically checked lazy module constructors and result types without eager imports.

## Checked composition

`ant.results.MeanSource` is the canonical mean input for decision and inverse-query APIs. Supported measurement, mechanism-composition, ledger, transported-counterfactual, bridge, observation and propagation producers provide `as_mean_source(...)`. Complete compatible producers can be supplied directly. Missing quantities, units, population or regime declarations require explicit adapter arguments; errors name the declaration and adapter.

Adapters preserve values and evidence; they do not grant native authority. A mean cannot substitute for a law, independent marginals cannot supply joint draws, and bounds, standard errors and predictive uncertainty retain their scientific meanings and licenses.

Callback executions belong to their session. Passing an execution from another session or tampering with its declaration/request/output identities is refused. Integer history indices refer to the receiving session. Use `execution.export()` and explicit `session.resume(...)` to transfer across sessions.

## Bytes-first persistence

`export(...)` returns bytes. Replace receipt access such as `exported.artifact` with ordinary bytes, or use `object.artifact(...)` to obtain `ExportedArtifact[T]` with `.data`, `.kind`, `.expectation` and immutable `.metadata`. Ledger carried/not-carried receipts and other family-specific export information remain in metadata. Explicit query or record selection is still required where applicable.

Loaded analysis payloads are available through `loaded.decoded_artifact`; `loaded.artifact()` now creates the common export envelope. Replace prior `loaded.artifact.payload` access with `loaded.decoded_artifact.payload`, or use `loaded.decoded_artifact.to_dict()` for an editable copy.

`ant.artifacts.inspect(data_or_artifact)` reads metadata without scientific execution. `ant.load(data_or_artifact, expected=..., context=...)` dispatches to the existing native family consumer and returns its specialized consumed object. Retain expectations separately from the bytes: reading an expectation out of an envelope or container during consumption does not establish an independent identity binding. Required family expectations remain mandatory.

Acceptance distinguishes identity binding, replayability and explicit resumability. Loading does not invoke callbacks or restore a live study. `LoadContext` carries existing bundle source declarations and actual native claim bindings. Unknown recognized formats remain inspectable and forwardable, with scientific consumption unavailable; malformed bytes remain errors. Bundle insertion accepts bytes, envelopes and supported exporting objects.

## Transport-grid parity

`ant.transport.advanced.estimate_augmented_response_grid(...)` exposes the existing Rust augmented response-grid evaluator. Supply its checked identification certificate and keyword arguments for outcome, trial membership, selection probabilities, grid, observed regression, target regression and response weights. The grid-dependent inputs have shape `(grid_size, row_count)` and use grid-major native ordering. The typed result includes means, grid, source effective sample sizes and selection-overlap diagnostics. Signed local weights remain supported. The utility remains point-only and grants no estimator, interval or retained-study license.
