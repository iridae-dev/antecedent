# Python 2.4 → 3.0 migration

The 3.0 lifecycle separates preparation from execution and uses immutable prepared handles. Scientific declarations remain explicit. Rust owns identification, numerical calculations, canonical identities and independent artifact consumption.

## Preparation and exploration

| 2.4 pattern | 3.0 operation |
| --- | --- |
| Loose `seed=`, `threads=`, cancellation, resource and observer arguments | Reusable `execution=ant.Execution(...)` |
| Loose `bootstrap=` | Scientific `inference=ant.Frequentist(bootstrap=...)` |
| A mutable study's latest result | Retain the returned `Outcome`; `outcome.study` retains its completed preparation |
| `study.refresh(new_data)` | `branch = ant.rebind(study, data=new_data)` then `ant.estimate(branch)` |
| Replace query/data through mutable methods | `ant.reconfigure(study, query=...)` for declarations; `ant.rebind` for observations |
| `study.inspect_plan()` | `study.inspect()` before execution; inspect each returned outcome separately |
| Run discovery implicitly while preparing an analysis | Execute discovery explicitly and review the resulting structure before analysis |
| `return_posterior_artifact=True` and `result.posterior.artifact` | Execute normally, then select `result.export(quantity="posterior")` |
| Module-level `identify.estimate(stage, data)` | `stage.prepare(data, inference=..., execution=...)`, then `ant.estimate(...)` |

For a runnable setup, use the [README example](../../README.md#install-and-use-antecedent). Its lifecycle is:

```python
import antecedent as ant

data = ant.data.table(frame)
study = ant.prepare(
    data, graph=graph, query=query,
    inference=ant.Frequentist(bootstrap=25),
    execution=ant.Execution(seed=19, threads=4),
)
result = ant.estimate(study)
updated = ant.rebind(study, data=new_data)
alternative = ant.reconfigure(study, query=other_query)
updated_result = ant.estimate(updated)
```

This snippet continues an application with declared data, graph and queries. Branching does not execute the branch or change earlier results. `study.rebind(data=...)`, `study.reconfigure(...)` and `study.estimate()` delegate to the same functions. Inspect `branch.reuse` for the retained and invalidated work. Population retargeting remains a scientific operation requiring population declarations and compatible retained evidence.

NumPy/frame inputs enter owned native storage. Subsequent mutation of the source cannot change a prepared study. Reuse the owned `ant.data.table(...)` handle across compatible preparations. Requested conversions and serialization are explicit materialization boundaries.

## Outcomes and refusals

Execution returns `Outcome`. Read `result.answer`, `result.inspect()`, `result.uncertainty`, `result.support`, `result.assumptions`, `result.diagnostics`, `result.provenance` and `result.identities`. `result.value` contains the specialized successful result. A scientific refusal has `result.refusal` and an explicitly refused answer; it is not a missing point estimate. Bounds and uncertainty intervals retain distinct meanings.

Valid scientific questions that cannot be answered return refusals with reason codes and available obligations/next actions. Invalid arguments, cancellation, resource failures, implementation failures and callback exceptions raise errors. Observer exceptions retain their original object and traceback.

`on_refusal="describe"` keeps the causal refusal as the primary outcome and attaches a separate `result.associational` outcome plus `result.evidence_plan`. Selecting an export requires `quantity="refusal"` or `quantity="associational"`; the associational answer does not acquire a causal interpretation.

## Export and independent load

`artifact = result.export()` returns a typed `ExportedArtifact`. `bytes(artifact)` exposes the encoding. Retain `artifact.expectation` separately at the producing side, then pass it explicitly as `expected=` to `ant.load`. Remove `.artifact()` conversion calls and nested receipt-byte extraction.

```python
artifact = result.export()
expected = artifact.expectation
encoded = bytes(artifact)
loaded = ant.load(encoded, expected=expected)
print(loaded.acceptance)
print(loaded.inspect())
```

This continuation uses an already executed result. Loading invokes the format's independent native consumer. Read acceptance for verification, identity binding, replay and resume standing. A loaded result has no reconstructed live study or dataset. Expectations read from the incoming container are not independent evidence of the expected identity.

An outcome with several possible scientific inputs requires explicit selection. Preserve units, populations, dependence, aligned draws and scientific bridge declarations. A mean does not become a distribution by passing it into another function.

Policy-program artifacts retain their existing encoding and represent checked declarations, not a saved simulated value. Independent loading additionally needs the original ordered variable names through `LoadContext(supplied_sources={"names": names})`. Header recognition alone grants no scientific acceptance.

## Cyclic and feedback models

Cyclic preparations use the same explicit execution controls and common operations. For example, this fully specified linear feedback system has `B = 0.5 A` after an intervention fixes `A`:

```python
import antecedent as ant
from antecedent.cyclic import LinearCyclicModel, World
from antecedent.intervention import Set

model = LinearCyclicModel(
    ("A", "B"), (0.0, 0.4, 0.5, 0.0), (1.0, 0.0, 0.0, 1.0),
)
study = model.worlds(
    [World(1, Set("A", 1.0))], component_id="feedback",
    source_id="specified-model", certifying_evidence=["declared-equations"],
)
branch = ant.reconfigure(study, worlds=[World(2, Set("A", 2.0))])
result = branch.interventions()
assert result.accepted
assert result.value[2].mean("B") == 1.0
```

Use typed evidence selectors and schemas to declare quantities, units and populations before composition. Compatible system/family views share their native fitted model; changed experimental observations invalidate that fit. Dynamic uncertainty declarations keep their statistical budgets, while seeds and execution controls use `Execution`. Remove seeds from sampling/optimizer/uncertainty declarations and remove the old mutable cyclic refresh/retarget spellings.

For nonlinear fitting, held-out joint interventions, within-system counterfactuals and fresh-process replay, run `examples/python/general_cyclic_systems.py`. Answers remain conditional on the specified or fitted model and its declared equilibrium/selection assumptions. These numerical and ownership checks do not establish calibration or attestation.

## Treatment-model nuisance products

Use the prepared study with `nuisance_scores.treatment_score_posterior` or its
prepared-study convenience method. This operation explicitly fits the treatment
model; preparation and inspection do not fit it. Keep prior scale, draw count,
positivity band and prediction rows on the scientific operation. Supply seed,
threads, cancellation and resource limits through `Execution`.

The earlier method defaulted to seed 0. The common execution default is seed 1;
pass `Execution(seed=0)` to reproduce the earlier draw stream. The Gaussian prior,
draw-count and positivity defaults are unchanged.

The likelihood follows the study's analysis mask and missing-data declaration on
treatment, outcome and certified adjustments. The outcome selects the analysis
cohort but is not a treatment-model predictor. Unsupported sampling weights
produce a refusal. `summary_rows` uses original physical row positions: an
excluded row can receive a prediction when its adjustment predictors are observed.

The returned outcome has immutable named summaries and bounded inspection.
Laplace uncertainty describes the treatment-model nuisance; it does not establish
an effect posterior or license a causal weighting distribution. Use `to_dict()`
to materialize the summaries and `export()` to materialize the artifact.

## Selected posterior records

Select a posterior after execution, without another fit. This continuation uses the application inputs from the preparation example:

```python
posterior_result = ant.analyze(
    frame, graph=graph, query=query,
    inference=ant.Bayesian(n_draws=32, backend="conjugate"),
    execution=ant.Execution(seed=19), refute=False,
)
posterior_artifact = posterior_result.export(quantity="posterior")
posterior_record = ant.load(
    posterior_artifact, expected=posterior_artifact.expectation,
)
ate_record = posterior_record.value.quantity("ate")
```

The native consumer validates the historical posterior encoding. Its sealed record contains summaries and any retained draws, with no live study or training data. The optional expectation binds the encoding digest; it does not establish an absent causal claim or grant replay. Select a named quantity when several are present. Reading an effect mean does not turn that mean into a predictive distribution.

## Population retargeting from retained scores

Population retargeting uses a completed study with compatible scores and explicit weight dependencies. It does not rebind observations or fit another score model:

```python
import numpy as np

population_result = ant.analyze(
    frame,
    graph=[("z", "treatment"), ("z", "outcome"), ("treatment", "outcome")],
    query=ant.AverageEffect("treatment", "outcome"), estimator="aipw",
    inference=ant.Frequentist(bootstrap=0), refute=False,
)
population_study = population_result.study
targeted = population_study.retarget(
    np.exp(np.asarray(frame["z"]) / 3), depends_on=["z"],
)
targeted_artifact = targeted.export()
targeted_loaded = ant.load(
    targeted_artifact, expected=targeted_artifact.expectation,
)
```

This example explicitly declares `z` as a common cause. Rust checks score availability, the binding to the original rows, and the declared dependencies. Nonconstant weights must be functions of the certified adjustment set and cannot depend on treatment descendants. The original answer and completed study stay unchanged; loading the weighted answer reconstructs neither.

### Trial transport and operational seeds

Prepare certified trial AIPW through `ant.prepare(trial_data, query=trial_query,
provider=transport.TrialAipw(...), inference=transport.TransportInference(...),
execution=ant.Execution(seed=8))`, where `trial_query` is an
`advanced.TrialAipwQuery`. Execute with `ant.estimate(study)`. The duplicate
public `advanced.prepare_trial` factory has been removed.

`TransportInference` retains its bootstrap count and nominal coverage.
Its operational `seed` moved to `Execution.seed`, together with seed fields
previously declared on `StatisticalTransportQuery` and
`TransportResponseGridQuery`. Their omitted numerical defaults are unchanged.
For example, replace `TransportInference(bootstrap=199, seed=8)` with
`TransportInference(bootstrap=199)` and pass `execution=ant.Execution(seed=8)`
to preparation. The same stream controls cross-fit splitting and outer bootstrap.

Use `ant.rebind(study, data=new_trial_data)` for new rows and
`ant.reconfigure(study, inference=transport.TransportInference(bootstrap=0))`
for a point-only branch. These return new studies without fitting. Trial
scientific reconfiguration revalidates its declarations against the retained
native snapshot; mutating arrays supplied earlier cannot change that branch.
Changing the row sampling design or variable coordinate schema requires a new
preparation. Bounds, nominal intervals, and calibration remain distinct.
