# Pre-T10 transport and ML lifecycle

The shared vocabulary is `prepare → inspect → estimate → export → load`.
A refresh is explicit and atomic: failed replacement validation or execution
leaves the previous study usable. Display projections never authorize execution.

## Structured learners

Use `antecedent.learners` specifications in DML, DR-Learner and transport:

```python
from antecedent.estimators import DRLearner
from antecedent.learners import Ridge, Logistic, GradientBoostedTrees

estimator = DRLearner(
    outcome=Ridge(penalty=0.1),
    treatment=Logistic(),
    final_learner=GradientBoostedTrees(trees=100, depth=3, learning_rate=0.05),
)
```

Legacy learner strings remain accepted. Parameters are validated in Python and
Rust; scientific identities include the actual settings. Auto selection remains
inside training folds. The public specifications mirror existing Rust providers;
this change does not invent additional provider hyperparameters.

Explicit `outcome=`, `treatment=` and `final_learner=` settings must support their
prediction task; incompatible specifications are refused. The legacy shared
`learner=` convenience adapts a specification to each nuisance task at
configuration time, so execution identity records the actual configured learners.

## Retained effect prediction

DR-Learner and causal-forest results expose `result.fitted_model`:

```python
from antecedent.prediction import FittedEffectModel
model = result.fitted_model
points = model.predict(new_named_columns)
loaded_model = FittedEffectModel.load(model.export())
assert loaded_model.predict(new_named_columns) == points
```

The artifact contains the complete parent claim, ordered feature schema,
intercept handling and fitted numerical state. Loading verifies the claim;
prediction checks missing/duplicate/nonfinite columns and never refits.
Unrelated columns are ignored, and columns may be supplied in any order.

Parametric CPU models, the CPU tree providers and native honest causal forests
have portable numerical codecs. Optional neural models do not yet have a
portable codec. Unsupported prediction versions refuse prediction while the
scientific result remains consumable when its optional payload schema is readable.
A completely unknown payload shape still needs an explicit future migration.

Training-sample CATE values, new-data predictions, marginal ATE intervals and
pointwise CATE intervals are separate products. New-data prediction returns
points with `prediction_only` uncertainty; it does not borrow the ATE interval.

## Transport requests

The preferred entrypoint is `transport.prepare(request, data, ...)`:

```python
from antecedent import transport

request = transport.StatisticalTransportQuery(identification, catalog, {"a": 1.0})
study = transport.prepare(
    request, data,
    provider=transport.LearnedCategorical(),
    inference=transport.TransportInference(bootstrap=199, seed=7),
    controls=transport.TransportControls(memory_bytes=256_000_000),
)
result = study.estimate()
```

Exact and finite-grid requests use this entrypoint as well. Existing
`prepare_exact`, `prepare_statistical` and `prepare_response_grid` remain
migration wrappers. The three-positional-argument identification/catalog/data
form remains available with explicit `at=`. Execution accepts cancellation;
changing frozen seed or inference settings requires preparation.

`TransportContrast` exposes `estimate`, `interval`, `reason` and
`coverage_target`. `TransportUncertainty` exposes availability, reasons,
intervals and paired replicate IDs. Transitional mapping reads remain, with
immutable tuples for arrays; use `to_dict()` for mutable JSON-style lists.

## Two distinct learned transport routes

`LearnedCategorical` fits one coherent chain-factorized law per physical dataset
and intervention world. All marginals and conditionals use that law. The
coordinate/category order, learner settings and empirical counts are bound into
the execution. Dataset aliases share a fit; outer replicates and grid coordinates
share each refitted law. Empirical conditioning support is still required even
when a model predicts positive probabilities. This is model-based plug-in
estimation, without a double-robustness or calibration claim. Cartesian limits
still apply.

`TrialAipwQuery` with `TrialAipwData` and `TrialAipw` fits source-arm outcome models
and observed-sample membership probabilities on shared cross-fit folds. Known
source randomization probabilities are required. Only a checked direct or
baseline-standardization binary contrast is supported. Covariates must match
the certificate.

Declare `sampling="independent_samples"` for a separately sampled representative
target: source and target sample sizes are preserved in each bootstrap draw.
Declare `sampling="nested_cohort"` for one IID cohort: the estimand is its
**nonparticipant** contrast and the cohort is resampled jointly. This is not a
whole-cohort ATE. Clustered, linked, unknown and weighted designs are unsupported.
The target sample declaration is a user assumption, not inferred from the data.

Bootstrap refits preserve original fold IDs for duplicated sampled units so one
unit cannot enter both training and validation. Treatment-arm contrasts remain
paired. Trial replicate failures withhold intervals. Artifacts replay the graph
identification, score and interval bookkeeping; they do not prove nuisance
consistency or rerun model fitting.

## Ownership and compatibility

Core owns reasoning and located grid failures. Learn owns fitted prediction and
finite categorical laws; estimate owns scores and fits; the facade owns prepared
execution; I/O owns durable grid records and container assembly.

Grid artifact v2 binds retained point-evidence digests and encodes child artifacts
only on export. Statistical scalar/grid execution reuses the original fitted
point laws; outer bootstrap datasets are refitted independently. Readers retain v1 verification and round-trip behavior. Exact
coordinate plans are compiled at preparation and reused. Statistical raw samples
are still required for refreshed estimation after portable consumption.

Nuisance reuse shares immutable prediction bundles. A cache-wide lock only
selects the key; fitting uses a per-key lock with cancellation-aware waiting.
Retained fold assignments and original row identities participate in cache keys. Failed or cancelled fits do not
publish predictions. The cache retains a bounded number of idle keys.

## Validation and T10

Run `examples/python/cohesive_ml_transport.py` for an executable workflow.
`benchmarks/cohesion/baseline.py` records release-extension latency, Python
allocations and process peak RSS on fixed workloads. These are current-tree
baselines, not before/after speedup claims. `cargo +1.97.1 bench -p antecedent --bench cohesion_allocations --features ml-full`
adds allocator-instrumented latency, native allocation-call counts, allocated bytes and peak incremental live
bytes under an explicit one-thread execution budget. It compares fresh nuisance
fits with warm reuse on identical inputs and asserts matching scientific values.
It excludes foreign direct `malloc`; process RSS remains separately measured.
A controlled before/after branch comparison is still required for branch-wide
speedup claims.

The new inferential routes are nominal and visibly uncalibrated. Full calibration,
coverage-registry rebinding and acceptance of coverage evidence remain T10 work.
Bounded numerical, lifecycle and misspecification tests are not coverage evidence.
