**R1 — Include shared numerical dependencies in calibration attestation**

Location: [record_facets](../../scripts/calibration_facets.py), lines 545–562, and [calibration_surface.list](../../scripts/calibration_surface.list), the `core` assignments.

`record_facets` deliberately excludes `core`. Yet `core` owns the shared least-squares implementation, conjugate posterior backend, bootstrap utilities, RNG implementation, temporal uncertainty helpers, facade dispatch, dependency manifests, and toolchain. An edit to any of those can change the very numbers the stored records measure without invalidating a single record.

The dependency probe checked `estimate/src/util.rs`, `stats/src/faer_backend.rs`, `prob/src/conjugate.rs`, `kernels/src/rng.rs`, and the facade's execution dispatch. Each invalidates **0 of 587** records. The actual attestation gate passed with 258 matching and 329 replay-attested records. That result establishes the implemented facet rule, not that all numerically relevant code matches the measured implementation. In particular, a fix for R3 could retain existing Bayesian calibration labels without measurement under this rule.

Restore conservative shared-dependency invalidation, or map the complete transitive numerical dependency set to each record. Use reviewed, exercised replay waivers for changes that cannot move numbers rather than excluding an entire shared-code category. Closure requires mutation tests showing that OLS, bootstrap, conjugate, RNG, and toolchain/dependency changes make the appropriate records stale. Then reassess the existing registry; this finding does not assert that every recorded coverage figure is numerically wrong.

**R2 — Reject the invalid treatment-descendant instrument**

Location: [is_valid_instrument](../../crates/antecedent-identify/src/iv.rs), lines 200–216.

For `U → T`, `U → Y`, `T → Y`, `T → Z`, the identifier returns `Z` with status `IdentifiedUnderParametricRestrictions`. It tests relevance in the original graph, then deletes **all** outgoing treatment edges. Deleting `T → Z` destroys the path that reveals the candidate's dependence on the outcome disturbance.

A linear Gaussian counterexample already satisfies the stated parametric setting: independent unit-variance errors, `T = U + eT`, `Y = 2T + U + eY`, `Z = T + eZ`. The true treatment effect is 2, but the population IV ratio is `Cov(Z,Y)/Cov(Z,T) = 5/2`. The probe confirms that the library offers this invalid instrument. This affects the direct identifier and the IV candidates collected by `AutoIdentifier`; it is not a claim that every default estimator selects that candidate.

Implement the full validity conditions for the supported total-effect IV criterion, including the relevant descendant restriction. Do not generalize specialized descendant-IV identification results to an ordinary unadjusted ratio; such methods require additional conditions and different constructions ([Chan and Kuroki, 2010](https://proceedings.mlr.press/v9/chan10a/chan10a.pdf)). Closure requires this graph to reject `Z`, plus positive controls for valid instruments and proxies of valid instruments.

**R3 — Replace address-only conjugate cache identity**

Location: [ConjugateGramKey](../../crates/antecedent-prob/src/backend.rs), lines 132–155, and [ensure_conjugate_gram](../../crates/antecedent-prob/src/conjugate.rs).

The cache key contains design and weight addresses plus shape, but retains neither an owning identity nor the data contents. A new allocation can reuse a released design's address. Recomputing `Xᵀy` while retaining the old `XᵀX` then combines statistics from different datasets.

The probe fits 32 rows with `X=1`, releases that allocation, and obtains a newly allocated `X=2` buffer at the recycled address. With `Y=2` and known residual variance, the reused workspace reports posterior mean **3.9987503905**, while a fresh workspace reports **0.9999218811**. No in-place mutation is involved, so the private comment asking callers to allocate new slices does not prevent the defect.

Use an immutable prepared-design owner/version, a complete content identity, or recompute the Gram when such an identity is unavailable. An explicit invalidation method cannot require callers to detect allocator reuse. Closure requires fresh/reused equivalence across new allocations, changed weights, changed design contents, and repeated prepare/fit cycles. The allocator probe explicitly reports whether reuse occurred; allocator behavior is platform-dependent.

**R4 — Preserve Gaussian BIC under a change of units**

Location: [gaussian_bic_local](../../crates/antecedent-state/src/graph_score.rs), line 249.

The score silently replaces every residual variance below `1e-12` by `1e-12`. When both candidate fits cross that floor, their likelihood difference disappears and only the complexity penalty remains. This is not a Gaussian BIC calculation on the supplied data.

For a 100-row noisy linear relation, the executed score difference `score(X→Y) − score(empty)` is **+297.4089531**. Multiplying only `Y` by `1e-8` changes it to **−2.3025851**. The preferred graph reverses even though the statistical problem is unchanged. Analytically, rescaling an outcome by positive `c` adds the same `−n log(c)` term to both fitted Gaussian log likelihoods, so their difference must remain unchanged. The shared scorer feeds exact and MCMC graph-posterior inference.

Use the actual positive variance with stable scaling, and explicitly handle truly degenerate fits. Also audit predictor scaling in the normal-equation/inversion path; simply deleting the variance floor does not establish all unit invariances. Closure requires score-difference and posterior-weight invariance over meaningful predictor/outcome unit changes, including small but nonzero residual variance.

**R5 — Prune minimal adjustment search and bound its work**

Location: [BackdoorIdentifier::identify](../../crates/antecedent-identify/src/backdoor.rs), lines 311–355.

With the default `minimal_only=true`, finding the empty adjustment set means no other inclusion-minimal set can exist. Nevertheless, the implementation visits every remaining subset, performs d-separation, and only then rejects supersets of the already found set. `max_results=64` never stops the loop because only one qualifying result exists. Ancestor screening occurs only above the 40-candidate cap.

For `T→Y` plus isolated variables, the probe counted **1,024**, **65,536**, and **1,048,576** examinations at 10, 16, and 20 candidates. The last took about 4.4 seconds in the recorded development-profile run. Forty candidates imply `2^40` visits by the same loop; no runtime extrapolation was measured. This also matters to `AutoIdentifier`, which attempts backdoor identification before returning its combined results.

Prune supersets during generation, short-circuit an empty minimal set, and use a visited-work/cancellation budget that bounds failed searches too. Preserve sound completeness reporting when a budget is exhausted. Closure requires adversarial wide, sparse graphs and hard confounded graphs; the current eight-covariate benchmark does not exercise this failure mode.

**R6 — Refuse or honor covariates supplied to Wald IV**

Location: [WaldIv::fit](../../crates/antecedent-estimate/src/iv.rs), lines 280–296; `prepare_iv_problem` accepts and constructs an exogenous design earlier in the same file.

The shared prepared problem carries `adjustment_set` and `exogenous_matrix`, but Wald fitting and its bootstrap use only `Z`, `T`, and `Y`. A conditionally valid instrument is thereby treated as unconditionally valid without a refusal or disclosure.

The probe supplies eight rows with binary `Z`, a covariate `U` whose arm means are 0.25 and 0.75, `T=Z+U`, and `Y=2T+3U`. On the same covariate-bearing prepared problem, Wald returns **3**, while 2SLS returns **2.000000000000001**, matching the structural effect **2**. This is a defect of the public covariate-bearing Wald route; the automatic IV identifier currently emits empty adjustment sets.

Either explicitly reject nonempty adjustment sets in Wald and direct callers to 2SLS, or implement the intended conditional estimator with matching uncertainty. Closure requires this example through preparation as well as fitting, including bootstrap behavior.

**R7 — Do not use three observations as kNN data identity**

Location: [knn_input_fingerprint](../../crates/antecedent-stats/src/ci/advanced.rs), lines 202–227.

The fingerprint hashes addresses, lengths, and only observations `0`, `n/2`, and `n−1`. Changing another observation preserves the fingerprint. Even a new `test_batch_adhoc` call with a newly prepared request can retain the old neighbor index and feature matrix in a reused workspace.

After changing `Y[7]` in a 30-row input, the reused workspace reports the old statistic **−1.5084944665**; a fresh workspace reports **−33.9631957648**. In this particular nine-permutation probe, both p-values happen to be 0.1; the finding is the demonstrably stale statistic and incoherent observed/null inputs, not an asserted p-value difference for that example.

Bind the cache to an immutable dataset identity/version or compare/hash the complete relevant content. Closure requires changes at unsampled positions, changed conditioning columns, and workspace reuse across distinct prepared sessions.

**R8 — Stabilize incremental OLS residual variance**

Location: [LinearOlsSuffStats::residual_variance](../../crates/antecedent-state/src/suff_stats.rs), lines 113–118.

Computing `yᵀy − βᵀXᵀy` subtracts nearly equal large values, then `.max(0)` turns cancellation into apparent zero residual uncertainty. For an intercept-only fit of `1e12 + [-2,-1,0,1,2]`, the probe returns **0** instead of the exact unbiased residual variance **2.5**. These observations and differences are representable in `f64`.

Maintain centered sufficient statistics, a stable incremental factorization, or another representation that preserves the residual scale. Treat an unrecoverable numeric state explicitly rather than presenting zero variance as evidence. Closure requires translation invariance and comparison with batch QR on large-offset, small-residual datasets, including append batches.

**R9 — Make the Arrow C-data invariant enforceable**

Location: [ArrowCColumn](../../crates/antecedent-data/src/arrow_ffi.rs), lines 26–46.

`ArrowCColumn` has public `array` and `schema` fields, and a safe `into_array` method calls the unsafe importer. Its safety justification says the pair is only constructed at a compliant FFI boundary, but the public Rust struct permits arbitrary pairings. A caller can construct an FFI array from one valid Arrow type and a schema for a different buffer layout using safe APIs. The wrapper then assumes those layouts agree; type/length processing after import cannot establish the original allocation's validity.

Arrow's importer explicitly requires a compliant C-data input ([Arrow API safety contract](https://docs.rs/arrow/latest/arrow/ffi/fn.from_ffi.html)). Preserve that requirement with private fields and an unsafe constructor/import operation, plus a safe constructor from an already validated owned Arrow array. Audit downstream safe functions accepting this wrapper. This is a static soundness finding; the review deliberately did not execute an out-of-bounds/UB example. Closure requires that incompatible pairs cannot reach unsafe import through entirely safe public calls.

The same precondition was checked in the locally installed, locked `arrow-array 54.3.1` source (`ffi.rs:264–275`); the public safe array/schema constructors were checked in `arrow-data` and `arrow-schema` 54.3.1. The linked online documentation is supplemental, not a substitute for checking the pinned dependency.

**R10 — Establish mmap immutability or expose its unsafe precondition**

Location: [MappedArtifactReader::open_path](../../crates/antecedent-io/src/reader.rs), lines 253–262, and [map_file_readonly](../../crates/antecedent-io/src/mmap_file.rs).

The safe constructor maps an arbitrary path and returns borrowed byte views. Opening one descriptor read-only does not prevent another descriptor or process from modifying/truncating the file. The internal safety comment imposes immutability on callers, but the safe public API neither establishes nor exposes that obligation. The reader also memoizes checksum verification under the same unsupported immutability assumption.

`memmap2` documents file-backed mapping as unsafe because subsequent in-process or external modification can cause undefined behavior ([memmap2 safety contract](https://docs.rs/memmap2/latest/memmap2/struct.Mmap.html#safety)). Provide a genuinely stable owned snapshot for the safe API, or expose an explicitly unsafe mapped constructor with a lifetime-wide immutability contract. Merely rehashing views or retaining a read-only descriptor is insufficient. This is a static soundness finding; no dangerous concurrent-write test was executed.

**R11 — Match calibration against the sample actually analyzed**

Location: [StudyResult::calibration_bases_with](../../crates/antecedent/src/analysis/contract.rs), line 1765 in the reviewed tree (`row_count: contract.row_count`); `data_row_count` supplies the input snapshot's raw count.

Complete-case filtering can leave far fewer usable observations than the input snapshot contains. Nevertheless, interval calibration is matched using the snapshot count. The recorded sample-size range therefore does not constrain the number of observations that actually informed the fit.

The public Python probe fits the same 100 complete observations three times. With 100 input rows it reports `scope_not_assessed / sample_size_outside_measured_range`. Adding 400 entirely missing rows changes the label to **calibrated**. Adding 900 instead changes it back to outside scope. All three fits return exactly the same estimate **2.1191746354035366** and analytic SE **0.12682625476532788**, and cite the same linear-adjustment coverage record. Empty information must not upgrade the evidentiary status of an unchanged interval. [Probe](v1.11-review/sample_scope.py); [output](v1.11-review/sample-scope-output.txt).

Record the actual analysis-sample basis used by each interval, and use the same convention in calibration measurements. Account explicitly for complete-case masks, trimmed/matched samples, lag-aligned temporal rows, and clusters where relevant; raw rows and effective sample size are distinct quantities and should not be substituted silently for each other. Closure requires calibration-label invariance to padding with discarded rows, plus tests for the other sample-selection routes and artifact roundtrips. The underlying assignment existed in committed HEAD before the concurrent uncertainty-reporting edits.

**Engineering assessment and repair strategy**

The crate split usefully separates graph representation, identification, estimation, numerical backends, and artifact transport. Explicit refusal states, provenance records, prepared analyses, and independent artifact consumers are valuable foundations. The defects above expose four cross-cutting gaps that local patches alone could leave elsewhere:

- **Cache identity is a semantic contract.** R3 and R7 need a shared immutable-data/version convention, not more sampled hashes or undocumented invalidation calls.
- **Numerical helpers have diverged.** QR in `antecedent-stats` already equilibrates columns, while graph scoring and incremental state use separate normal-equation paths. Dense Cholesky/inversion helpers also exist in both stats and prob with different validation behavior. Consolidate the appropriate low-level contracts without forcing unrelated statistical models into one abstraction; add shared finite-input, scaling, translation, and fresh/reused equivalence tests.
- **Budgets must constrain work, not just outputs.** R5 shows why a result cap is not a search budget. Audit other enumeration and allocation paths using the same distinction, and measure adversarial workloads as well as small happy-path benchmarks.
- **Evidence dependencies and scope must follow the executed analysis.** A gate can faithfully implement an insufficient rule. R1 and R11 need negative tests at the claim boundary, alongside the existing manifest/schema self-tests.

Keep corrections separate and reviewable. First repair the evidence dependency rule and safety boundaries; fix numerical/identification issues with consuming regressions; then remeasure affected calibration records and timing budgets. Do not close issues merely by renaming a claim, widening a tolerance, weakening the support matrix, or retaining a green historical attestation.
