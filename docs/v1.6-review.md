# 1.6.0 claim review

Reviewed the existing 1.6.0 working tree against its release notes, evidence
ledger, support matrix, Rust implementation, Python facade, and result artifacts.
The corrections below preserve the documented identification boundaries.

## Corrections

| Finding | Correction and regression evidence |
| --- | --- |
| Deterministic thinning of component draws could alias their order and distort mixture quantiles. For alternating −1/+1 draws in a half-weight component, the old selector retained only +1. | Sample a categorical graph and then its empirical posterior using a fixed reproducible random stream. `categorical_draws_do_not_alias_ordered_component_samples` checks both tails. |
| Computing mixture variance as E[X²] − E[X]² could erase small uncertainty around a large location. | Center both moment calculations. `large_location_does_not_erase_small_mixture_variance` pins variance 1 at location 10¹². |
| Invalid weights and ambiguous draw mappings were accepted; tiny weights could lose identified mass through subtraction or distort unidentified mass through an epsilon denominator. | Validate shapes, finite nonnegative weights, unique per-graph draw mappings, and nonempty finite positive-weight component draws. Sum identified mass directly and normalize by the actual positive total. Zero-weight atoms need no draws. Regression tests cover invalid and tiny weights. |
| Observation and frequentist DBN bootstraps could report uncertainty from a small surviving fraction of replicates. | Share the failure policy: at least two successes and no more than half of attempted replicates failed. Reject nonfinite replicates. Retain counts when bands are withheld. |
| DBN cancellation counted unattempted replicates as fit failures; observation cancellation did not reach the top-level result. | Track attempted replicates separately and propagate cancellation. `observation_bootstrap_tests` checks failed and cancelled runs. |
| Bayesian Sequence bands substituted Gaussian mean ± 1.96 SD for available posterior quantiles. | Use per-horizon posterior 2.5% and 97.5% quantiles. `bayesian_sequence_band_matches_posterior_quantiles` checks the public response against its posterior artifact. |
| Observation bootstrap memory checks omitted retained replicate surfaces, and block sizing used an optional history hint instead of the actual identified unfolding. | Include retained surface buffers in checked preflight arithmetic; derive the minimum block span from the horizon indexers. The temporal observation facade test checks that a budget sufficient only for output is refused. |
| Release/provenance prose implied exact underlying posterior moments and overstated the memory bound. | Specify empirical-component moments, finite Monte Carlo quantiles, a fixed aggregation stream, and a buffer preflight lower bound rather than total process-memory enforcement. |

## Mathematical and epistemic assessment

The graph-mixture target is conditional on identification; unidentified mass
remains a separate result axis. Exact moments refer to the supplied empirical
component posteriors, not an analytically integrated underlying posterior.
Sampling a model before its conditional posterior implements the mixture
operation, unlike averaging aligned component draws. This interpretation agrees
with the model-averaged posterior described in
[Bayesian model averaging via mixture model estimation](https://arxiv.org/abs/1711.10016).

The reviewed temporal paths retain horizon-specific identification and adjustment
sets. Completion enumeration supplies structural ranges, not posterior model
probabilities. Natural mediation remains scoped to the stated identified linear
DAG mechanisms; the PAG cross-world boundary stays closed. Multi-horizon
mediation remains pointwise, and Bayesian observation-adjusted bands remain
unlicensed. Prior transfer does not create identification.

The bootstrap regressions establish implementation behavior. They do not establish
nominal repeated-sampling coverage for the newly implemented observation bands.
The sequential model assumptions and unassessed joint longitudinal support remain
explicit in results and release notes.

## Engineering and performance

The fixes share bootstrap success policy and observation-band reduction/attachment
instead of maintaining separate curve and Sequence implementations. Quantile
reduction reuses scratch capacity across cells. Sequence handling moves the
single-horizon posterior instead of cloning it.

Categorical selection now searches a precomputed CDF in O(log K) per draw instead
of scanning K graphs. Computing empirical moments still necessarily reads all
K × D component values; this is not an end-to-end O(D log K) claim. Output and
retained observation-bootstrap buffer checks fail before fitting when the stated
budget is insufficient. Model-fitting workspaces and allocator overhead are not
covered by this lower-bound check.

## Validation

- The broad `cargo test --quiet` run passed 1,944 tests with 33 ignored.
  Final-state focused facade tests passed 165 tests; the nine mixture regressions
  also passed. The broad run began before the final bootstrap follow-ups; those
  follow-ups were covered by the focused tests and rebuilt Python extension.
- Python release selection: 211 tests against a rebuilt native extension.
- Clippy with warnings denied for the facade, estimator, and IO crates; Rust
  formatting; Python Ruff and mypy checks.
- Support matrix, metadata, documentation, provenance, and evidence-reachability
  gates. Regenerating the support matrix produced identical file contents.
- Temporal Criterion benchmark smoke in the development profile, including
  sustained windows, Bayesian surfaces, multiple horizons, and a 100,000-row
  intervention shift. This is execution/allocation-path validation, not a new
  release-profile throughput baseline.

This review does not replace the scheduled calibration suite, platform wheel
matrix, or a release-profile performance baseline. The entire release gate was
not run: its clean-git checks are incompatible with the pre-existing uncommitted
release work. Relevant consistency gates were run directly, and generated-file
freshness was checked against the starting working-tree contents.
