## Closed inherited routes

Every route that was closed at the tag, from its stage rows and its registry. The reason code is the one the tag emitted and is kept until a new record licenses the route. Dispositions:

- `prerequisite`: new work must consume this route's licensed form first; it stays closed until then.
- `deliberate_refusal`: new work touches the route's neighbourhood and keeps refusing it, with its reason code unchanged.
- `reopened_under_new_record`: a new promotion record owns the route's replacement; the inherited route stays closed until that record is promoted.
- `unclassified`: no work in the current composition scope touches the route; it remains closed unchanged.

## Identity and API migration decisions

Decisions the refactored base made to identities and public surfaces since the tag. `--check` verifies that each pointer's file exists and still contains its anchor text.

| Area | Decision | Pointer |
| --- | --- | --- |
| Persisted identity digests | Persisted identities and receipts (design, decision, io artifact, estimate, completion and scenario digests) are hashed through one canonical length-delimited writer under named domains. Digests of these routes change value and earlier artifacts are not replayed. | `CHANGELOG.md` |
| Stage identities | Selective-recalculation stage identities encode every input as a typed, length-delimited field (floats by bit pattern, enums by stable tag) instead of Debug text; every stage identity, the callback request digest and the batch estimator fingerprint change value. | `CHANGELOG.md` |
| Request identities | Provider requests are hashed by content (JSON values, arrays and column tables by dtype, shape and bytes); the repr fallback is removed and a request with no canonical form refuses. | `CHANGELOG.md` |
| External callback request identity | The callback request digest now binds the planner branch, so identity reuse across branches is refused and replay is branch-bound. | `docs/refactor-verification.md` |
| Python JSON identities | Every Python digest over a JSON document is the Rust canonical digest under a named domain; contract, graph, request, report and sample identities move and previously exported reports no longer validate their stored digest. | `CHANGELOG.md` |
| Provider identity and receipt | One provider object identity and one provider-verification receipt carry the registered name, spec digest, request digest and operations; receipts load only under the digest a consumer retained. | `CHANGELOG.md` |
| Canonical JSON | Non-finite floats have no digest and are refused before hashing; finite digests are unchanged. | `CHANGELOG.md` |
| Canonical, data and execution identity roles | The canonical claim identity binds scientific fields and the estimand, the data identity binds observation and sampling fields, and the numerical execution identity adds provider, options, seed, limits and uncertainty method; one field's digest never substitutes for another. | `parity/identity_contract.md` |
| Wire and API surface | Estimator-free artifact container, wire types and digests move to antecedent-io-core with the antecedent-io root re-exporting them, so public paths and artifact bytes are unchanged; test-only container seams sit behind a test-util feature. | `CHANGELOG.md` |
| Public API narrowing | Items without a cross-crate reference are crate-private and the reviewed public-API snapshots under parity/public_api are the gate; removals and additions are itemised per crate in the changelog. | `CHANGELOG.md` |
| Verification limits of the refactor | Branch verification is not a calibration attestation; calibration-dependent acceptance checks remain closed until a legitimate measurement, and no inherited route was promoted by the refactor. | `docs/refactor-verification.md` |

## Reproduction

```text
python3 scripts/snapshot_promotion_baseline.py --check
python3 scripts/snapshot_promotion_baseline.py --write
python3 scripts/snapshot_promotion_baseline.py --write --tag <vX.Y.Z> --base <commit>
```

`--write` keeps existing route classifications and decisions and takes the base commit from the checked-in file unless `--base` is given (default: the current `HEAD`).
