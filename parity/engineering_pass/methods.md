## Implemented findings

### M1: Accepted portable numerical maps lacked a deserialization invariant

Paths: crates/antecedent-learn/src/portable.rs; caller crates/antecedent-model/src/tree.rs, crates/antecedent-estimate/src/smoothed_dose.rs.

Owner: learn/model numerical interchange. PortablePredictor derived Deserialize without validating version, coefficient shape, finite parameters, feature bounds or forward-only tree links. FittedPredictor::predict validates, but predict_trees_with deliberately skips a full payload scan after acceptance. A directly assembled malformed predictor could loop forever on a cyclic link or call an indexing closure with an invalid feature. Actual model TreeEnsemble::new validates once, owns an immutable Arc and uses the low-level method for every mechanism prediction; repeated full validation there would add needless per-draw tree scans.

Fix: deserialize through a private same-shape wire adapter and validate before acceptance. Retain the existing public fields/API and serialization shape. Add constant-cost feature and forward-link checks to the traversed nodes so the public low-level method cannot hang on malformed direct assembly. Do not merge additive tree sums, honest valid-vote means, logistic transformations and probability clipping: those are different fitted scientific semantics.

Regression evidence added: malformed links rejected by deserialize; direct cyclic traversal returns error; invalid feature is rejected before the supplied closure executes; valid linear roundtrip preserves payload; future version deserialize rejected. Existing test exports each CPU provider, roundtrips it and compares numerical predictions. Verification includes learn tests and model/estimate artifact consumers; executed results belong to the integration record. No identity or wire change for valid models; newly rejected invalid payloads previously violated documented invariants. No migration or golden update required.

### M2: Public Bayesian SPD solve could panic and malformed shape could allocate before refusal

Path: crates/antecedent-prob/src/linalg.rs. Callers: conjugate.rs Gaussian posterior and laplace.rs Hessian solve.

Owner: prob linear algebra. solve_spd_into returned Result and documented numerical refusal but delegated short RHS/output/scratch directly to unchecked kernel substitution. cholesky_spd allocated n.saturating_mul(n) elements before checking input length, permitting an overflowing malicious dimension to request an impossible allocation.

Fix: reject short RHS/output/scratch before any factor/output mutation; check n² overflow and input coverage before allocating Cholesky output. Keep the existing shared kernel factorization, pivot acceptance rule, inversion and arithmetic intact. Low-level kernel chol_solve_into remains an explicitly unchecked helper for checked factors/buffers; changing that signature would impose redundant validation/API churn on concrete internal callers.

Regression: each short vector position refuses with all buffers unchanged; usize::MAX dimension and short matrix refuse without allocation; existing known-system and NaN Hessian tests remain. Verification includes prob tests, conjugate/Laplace consumers and Bayesian conformance. Valid numerical outputs unchanged.

### M3: Fold-plan validation repeatedly rescanned the entire row set

Path: crates/antecedent-learn/src/crossfit.rs, complete_fold_count. Callers: cross_fit_with_folds and selected cross-fitting used by nuisance learners.

Owner: learn preparation. Validation did a complete row scan for each fold; the valid maximum 65,536-fold permutation required billions of comparisons before fitting.

Fix: maximum fold id plus a bounded boolean occupancy pass, at most 65,536 entries. Preserve rejection of absent zero, internal gaps, empty and singleton-fold plans, and the original fold numbering. Per-fold scientific train/validation splits and RNG are unchanged.

Regression: empty/singleton/missing-zero/internal-gap/max-id-gap plans refuse; complete reversed 65,536-fold plan accepted; existing fold wrap, stratification, cancellation and shared-lease tests retained. Verification includes learn tests and cross-fit resource gates. Time complexity changes from O(rows*folds) to O(rows+folds), at most 64KiB extra transient occupancy storage; no identity or accounting value changes.

### M4: Tiny attribution cache budgets still allocated a full dense index

Path: crates/antecedent-attribution/src/coalition.rs. Callers: shapley.rs exact enumeration and ordered decomposition.

Owner: attribution cache. enable_dense_index allocated up to 65,536 Option<CacheEntry> slots regardless of CachePolicy::max_bytes, including a budget of 32 bytes. Per-entry insertion refused correctly, but the index allocation itself could exceed the declared cache allowance by orders of magnitude.

Fix: compare the actual dense index storage size to the local cache allowance and retain the existing sparse map if the eager index alone exceeds it. The local payload byte accounting, replacement semantics, sticky saturation, lookup ordering and payoff evaluation remain identical. Do not rewrite the exact Shapley payoff table into a cache: the exact table deliberately evaluates each coalition once even when cache disabled/saturated, making its computation budget truthful.

Regression: max-player dense index does not allocate for a 32-byte cache; first payoff retained, second refused, lookup values and accounting/saturation preserved. Existing dense-index and serial/parallel bit-equivalence tests retained. Verification includes attribution tests. Allocation strategy changes; scientific outputs, cache stats and serialized artifacts do not.

### M5: Undefined posterior probabilities could publish finite scientific claims

Path: crates/antecedent-prob/src/posterior.rs. Actual caller chain: PosteriorDraws::probability_below -> estimate/bayesian/mod.rs CausalPosterior::probability_below -> python/src/ate_api.rs and python/src/lib.rs p_below publication.

Owner: prob posterior storage/publication. NaN failed draws compared false and remained in the denominator; e.g. [-1, NaN, 1] at zero published 1/3 as if the failed draw proved the effect nonnegative. Empty draws published 0.0. Both disagree with summarize's existing undefined/NaN policy and cannot be repaired by silently renormalizing the retained successful draws.

Fix: explicit numerical refusal for an empty column, any nonfinite draw, or a NaN threshold. Preserve +/-infinity as valid thresholds for finite draws. This is an intentional behavior correction for previously undefined probabilities; all finite, nonempty scientific outputs are unchanged. Python already propagates the Result error rather than requiring a parallel policy/conversion path. No artifact layout or valid identity change; no goldens repinned. Measurement implication: any historical measurement using failed draws as valid posterior probability must be rerun/refused rather than relabelled.

Also harden the same public storage boundary without breaking its released public fields: checked dimension multiplication at construction; checked offsets/ranges in column/get/batch/PosteriorBatch::column; malformed directly assembled columns get undefined summaries instead of panicking. Keeping public fields means complete invariant enforcement still belongs to constructors and fallible consumers; privatization is a coordinated public Rust API migration, not silently performed here.

Regressions: failed/empty/infinite draw probability refuses; NaN threshold refuses; infinite thresholds give 0/1 and finite mixed signs give 0.5; malformed public dimensions and manually assembled batch ranges return shape errors; malformed summaries remain NaN. Existing finite summary/quantile/layout oracles retained. Verification includes prob tests plus Bayesian and Python probability consumers.

### M7: Residual-fit cache exceeded its advertised bound and undercounted retained fit state

Path: crates/antecedent-estimate/src/serial_dependence.rs; owner: estimate serial-dependence preparation. Actual caller: long_run_tempering_factor -> residual_fit -> ResidualFit::new. The old global LRU retained its newest source even when it alone exceeded the 2^21-element cap, and counted only source rows and residuals while omitting Gram/AR/quadratic-stencil/info buffers.

Fix: account all retained f64 buffer capacities, use saturating sums, bypass insertion for an oversized entry and evict until the total fits, with no newest-entry exception. Recompute preserves exact fit results. Regression pads only an unused source Arc tail beyond the cap, so the numerical fit stays small; repeated calls return different Arc fits with identical residuals, model coordinates and df losses, and the oversized source never appears in the bounded cache. Existing content-key reuse and direct-fit comparison retained. Measurement implication: oversized repeated fits now recompute and runtime/fit-work may increase; bounded retention is the intentional engineering tradeoff. No scientific output, identity or artifact version changes.

### M8: Device panic poisoned the global training lock and broke promised CPU fallback

Paths: crates/antecedent-learn-burn/src/lib.rs and staged.rs; owner: neural provider lifecycle. Actual caller chain: device::fit_portable_wgpu_cancellable catches unwind from staged::fit_staged -> policy::fit_with_policy classifies Device failure -> fall_back_or_refuse -> train_cancellable. A staged device panic poisons TRAIN_LOCK; staged recovered that lock but direct CPU train refused with LockPoisoned, preventing the documented auto fallback.

Fix: one private training_guard recovers the unit lock for both routes and both hold it through the complete fit. The shared protected state is RNG sequencing; model/tensors/optimizer are fit-local and unwind, and every successful route reseeds before initialization. Correct misleading staged comment saying only seeding was serialized. Preserve exported LockPoisoned enum variant for API compatibility; no valid output or provenance change. Regression simulates a panic while holding the guard, then verifies both direct and staged CPU fits reproduce pre-panic seeded prediction bits. Existing RAII device admission unwind tests cover lease return; no GPU needed to test lock recovery. Verification includes learn-burn tests and neural feature integration when that release feature is enabled.

## M10: Residual fitting discarded the caller's cache and admission policy

Actual caller: `BayesianGComputationAte::fit(..., ctx)` → private `temper_likelihood` → `long_run_tempering_factor` → `residual_fit`. The former private boundary dropped ctx. Consequently, even a disabled cache or finite admission pool could consult and populate the process memo. M7's element cap alone could not satisfy that caller contract.

Fix: fit passes its context into temper_likelihood, which selects private `ResidualFitReuse` and forwards it to residual fitting. Disabled caching, any bounded cache policy, or any finite admission pool selects Uncached. That branch computes the same deterministic fit before hashing, locking, lookup or insertion; even an already-warm identical entry cannot override the caller. Enabled/unbounded caching with an unlimited pool retains the existing bounded content-verified memo. `memory_limit_bytes()` is derived from the admission pool capacity, so no independent finite-limit/unlimited-pool state escapes this guard. Existing entries authorized by another execution remain independently owned.

The production regressions invoke actual conjugate Bayesian fitting with temporal dependence. Restricted policies assert zero cache lookup/insertion, unchanged source/outcome Arc counts, no newly retained source identity and exact posterior equality before/after explicitly warming identical content. The unbounded-policy test asserts memo access and exact repeated posterior values; the existing content-cache test separately checks fit Arc identity. Per-thread test observations avoid clearing shared state or depending on concurrent eviction. Existing numerical fixtures explicitly select their permitted reuse policy.
