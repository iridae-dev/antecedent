## Implemented findings

1. **FND-01: repeated artifact loads falsely consume untouched-section accounting.** Owner: io-core reader. `ArtifactReader::load_section` and both mapped load paths decremented skipped counts on every successful call, even when revisiting the same section. A repeated metadata inspection could report a never-read blob as loaded/skipped=0. Fixed with private per-section successful-load bits and one shared `note_loaded` function. Per-call loaded bytes/load counts, mmap views and decompression work remain activity counters; skipped bytes/sections now count the actual untouched set. Failed reads never clear their skipped membership. Regression loads metadata three times through both readers, checks the untouched blob remains skipped, then loads it and checks final counts. Valid bytes and scientific identities are unaffected. Paths: `crates/antecedent-io-core/src/reader.rs`.

2. **FND-02: retained spill handles could silently retarget and delete replacements.** Owner: state disk retention. `SpillHandle` stored digest and key, but `reload`, `on_disk`, and `remove` used only the key. Replacing a key made an old prepared-state handle load a different result and delete its successor. Fixed private checked generation tokens in entries/handles; stale handles refuse reload, report false presence and cannot remove successors, including replacements with identical payload bytes. Registry key-based operations intentionally continue selecting the latest entry. Reload now reads its immutable snapshot while the registry lock pins the entry, so concurrent eviction/replacement cannot unlink it between lookup and read; decoding arbitrary `Spillable` code remains outside the mutex. Successful reload touches LRU only if the same generation remains. Sequence exhaustion now refuses instead of reusing a saturated generation/path. Regression exercises different- and same-content replacement. Paths: `crates/antecedent-state/src/disk_retention.rs`; actual prepared callers: `ols_refresh.rs::spill`, `weighted_refresh.rs::spill`, `conjugate_refresh.rs::spill`, `conjugate_block_refresh.rs::spill`, `covariance_refresh.rs::spill`. No spill-frame encoding changes.

3. **FND-03: spill reload could allocate arbitrarily enlarged external files.** Owner: state disk retention. The recorded frame size was charged to the registry but reload used unbounded `fs::read`. Fixed reading at most the reserved bytes plus one, rejecting unequal length before frame parsing/digest checks. This preserves a size mismatch as typed `StaleCache` and does not reserve an attacker-declared huge vector. Regression enlarges a spill and checks refusal/no successful reload count, then cleanup. Path: same as FND-02.

4. **FND-04: filtered DAG surgery destroyed scientific node labels.** Owner: graph DAG. `Dag::copy_filtered` recreated nodes with `with_variables(n)`, relabeling non-dense schema IDs and unfolded time slots into unrelated dense static IDs. Fixed preserving every `NodeRef` and dense order while retaining exactly the original edge predicates. Actual callers: identify `backdoor.rs::remove_outgoing_set`, `remove_nodes`, and `path_specific.rs::ancestors_avoiding`; benchmark `graph/benches/surgery.rs`. ADMG already distinguishes `CopyLabels::Preserve`/`StaticIndex`; DAG operation has one preservation contract. Regression covers static variables 7/3 and unfolded variable 7 at offsets -1/0, all/drop edge cases and unchanged source. Correct dense-static prior results/bytes unchanged; intentionally corrected output for mislabeled copies is an invariant repair, not a new encoding/version. Path: `crates/antecedent-graph/src/dag.rs`.

5. **FND-05: obsolete cancellation state survived only to support a synthetic reaper.** Owner: core execution. `LeaseSlot.cancelled` never changes in production and was read only by test-only `reap_cancelled`; real cancellation now correctly retains charges until cleanup. Removed the bit and dead reaper rather than suppressing warnings. Reworked its synthetic scan test into actual `close_slot` child-then-parent resource conservation, retaining unrelated leases. Production cancellation mechanism unchanged. Existing owner/child live-memory, cancellation wakes waiter, map cleanup, scratch refusal tests verify the real lifecycle. Path: `crates/antecedent-core/src/execution.rs`.

6. **FND-06: categorical construction trusted a bypassable public domain constructor.** Owner: data categorical. `CategoryDomain` is a public record and its fields can be built or edited directly. `CategoricalColumn::try_new` assumed the Other target had passed `CategoryDomain::try_new`, so it could silently rewrite unknown codes to another out-of-range code. Centralized private `CategoryDomain::validate` and invoked it at both domain and column construction. Regression directly constructs malformed domains (empty levels, invalid reference, invalid Other) and requires typed refusal. Existing well-formed domain and column encodings/identities unchanged. Path: `crates/antecedent-data/src/categorical.rs`.

## Cross-cutting review and dispositions

### Canonical ownership and dependency keys

Reviewed `core/canonical_encode.rs`, `core/identity.rs`, `core/value.rs`, `io-core/identity.rs`, `io-core/claim_identity.rs`, `io-core/dependency_key.rs`, `data/content_identity.rs`, `data/storage.rs`, `state/invalidation.rs` and shared artifact codec. Canonical scientific values are domain-separated BLAKE3 via `CanonicalWriter` and type-adjacent `CanonicalEncode`; IEEE float bits intentionally preserve signed zero/NaN payloads. `Value` equality/hash are bit-consistent; certificate equality intentionally does not coerce numeric variants (`same_intervention_level`). FNV keys are expressly in-memory cache aids, not portable scientific identity. Dependency classes/products are closed enums with explicit exhaustive class declarations; source/row/model/intervention/joint/inference/numerical dependencies should not be merged just because encodings look similar. Disposition: retain current scientific encodings and separation; no renumbering or silent golden update.

Data storage has a separate published v1 derive-key content format and memoizes it lazily in shared `OnceLock`; schema is bound separately by enclosing snapshot. Its bulk staging has exact-byte reference comparisons. Replacing it with a generic canonical helper would change published bytes, so sharing the policy does not justify merging the byte streams. Keep existing format, memoization and content-vs-schema distinction; verify existing `content_identity` tests.

Counts use `usize`→u64 conversions in existing encodings; on supported 32/64-bit targets they are lossless. Core `count` has a saturation fallback for hypothetical >64-bit usize targets whereas io-core `lossless_u64` rejects unsupported width at compilation. No supported-target collision was found. Disposition: no compatibility-changing refactor solely for an unsupported platform; owner core identity if adding >64-bit target support.

### Construction, deserialization and claims

Reviewed domain/query→wire conversion architecture in `io-core/query_wire.rs` (including scalar and longitudinal/sequential/history/association arms), container framing and codec version gate, `expr/program.rs`, `contract/claim.rs`, `contract/external_refusal.rs`, data storage and categorical construction. Wire records are intentionally syntax-bearing DTOs; serde decoding alone is not trusted execution. `decode_with_version` reads one CBOR item, checks version before deserializing its concrete payload, and rejects trailing bytes. Container manifest read bounds manifest allocation, cumulative logical bytes and duplicate section IDs; selected loads verify hash/decompress and declared sizes. Program construction bounds nodes/tables/depth, enforces backward child/table references and schema membership, then owns arena/schema/roots in `Arc`; compiled evaluation borrows this validated owner. Retain checked program boundary rather than expose unchecked construction.

Several core query constructors represent declarations pending contextual preparation, not globally valid executable contracts; schema/population/graph constraints require actual prepare/lower callers. Conversion should not introduce hidden fitting or claim scientific validity from mere serde success. Current specialized query conversions invoke their intrinsic validators where present. Disposition: preserve DTO/domain-vs-checked-execution split; do not make all query fields private in this bounded pass. Binding/facade owner must continue using checked preparation, not execute arbitrary DTOs.

Claims are classified by shared `contract::ClaimKind`, with explicit associational variant and noncausal predicate; `ClaimDomains` distinguishes NotClaimed from failed/unknown identification. Refusal construction in `contract/external_refusal.rs` shares one structured envelope and named stage/detail/capability/remedy fields; family-specific mappings retain their registered semantics. Keep scientific-method-specific messages/variants rather than collapse into generic strings. No observed justification for broad claim/refusal API churn. Integration owner verifies actual facade result classification, refusal fallback and host-record parity through executing routes.

Public record domains remain writable for API compatibility; enforce invariants at consuming checked constructors. FND-06 addresses the demonstrated categorical gap. This review does not assert every public record is intrinsically unforgeable. Future breaking encapsulation changes belong with public API/Python pass, with migration, not unannounced here.

### Ownership, cancellation and reachable panics

Reviewed `core/execution.rs` admission grant/reserve/credit/close/drop, cancellation notifications, `core/device_reservation/cpu_admission.rs`, `state/disk_retention.rs`, reader backing/verification. Admission grants use checked subtraction and checked lease IDs; releasing a parent credits its remainder and reparents live children, so children retain their holdings. Cancellation stops admission/wakes waiters but does not release live buffers. Fold/learner admissions own CPU and scratch leases; scratch failure drops CPU reservation. Drop/explicit release can panic on impossible credit overflow, with typed `try_release` for explicit callers; checked grants and conservation prevent caller-controlled overflow, and corrupted internal-state regression tests preserve refused holdings. Disposition: keep invariant panic rather than suppress conservation failure or silently release accounting; FND-05 removes obsolete conflicting cancellation representation.

Graph `DenseNodeId::from_index` panic requires an index above u32 range; graph constructors cap node space. Private reader indexing and mapped-section slice access depend on checked private construction; `locate_section` checks end bounds and returns typed IO refusal for truncation. `split_reals` is a crate-private checked-length consumer helper and explicitly requires caller length checks; no demonstrated unchecked public input route found in the reviewed paths. Do not replace these local invariants with misleading default values.

### Artifacts, resource lifecycle and compatibility

Reader owned snapshots remain independent of file replacement; mapped file interfaces are explicitly unsafe and document lifetime-wide external immutability. Per-section verification memo is sound only under that contract. No extra copies introduced to payloads; FND-01 adds one bit per indexed section. Inspection reads manifest/index only and does not evaluate scientific claims. `artifact_codec` already shares fixed-layout container writing/reading/versioning while preserving family refusals and payload semantics. Section decode and read limits remain bounded; measured accounting changes are intentional bug corrections, not scientific identity changes.

Spill registry writes frame via temporary path then rename, removes temp on failure, returns reservations through remove/eviction/drop and uses typed corruption refusals. FND-02/FND-03 tighten handle identity, read linearization and bounds. Disk IO remains serialized under registry mutex; this favors correct deletion/accounting and is bounded by registry frame budget. Do not claim this is a lock-contention performance improvement; final measurement owner should capture any large-spill concurrency workload before making such claims.

Open design limitation (explicit, not a new introduced defect): `SpillRegistry::new` documents that its directory belongs to that registry; two independent registries pointed at the same directory can collide because sequence IDs are registry-local. Actual callers take a supplied registry rather than auto-creating a shared global directory. Disposition: exclusive-directory precondition retained; owners must supply separate directories. A future multi-registry/shared-directory feature needs namespacing and ownership protocol, not a migration of existing spill bytes. Filesystem removal failures are best-effort under existing infallible remove/drop APIs; no guarantee of OS-level deletion after permission revocation can be made. Failing IO still surfaces at load/write boundaries.
