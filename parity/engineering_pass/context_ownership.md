# Caller context and retained numerical ownership

Owner: integration, with static/class routes reviewed by methods, temporal and
checked compilation by facade, and transport/evidence planning by foundations.
[Validation](validation.md) records executed checks and source snapshots. The
implemented chains below are source findings; the new context regressions still
require root execution against final source.

The audit followed actual `ExecutionContext` values through their consuming
callers. It found default production contexts and context-free helper calls
below context-bearing workflows, plus error conversions that turned resource
or cancellation failures into scientific unidentified mass. The fixes propagate
ownership through both ends of those chains.

| Implemented boundary | Ownership and preserved behavior |
| --- | --- |
| Bayesian fit → serial-dependence memo | Explicit reuse permission reaches residual fitting. Disabled/bounded caching and finite pools bypass lookup and retention, including warm entries. Opt-in unbounded process reuse remains capped; oversized fits do not enter it. Production-fit regressions passed in an earlier targeted follow-up. |
| Temporal class compile/prepare → per-atom enumeration | The caller or actual posterior worker context reaches configured identification and checked proof validation. Contextual calls bypass the process envelope memo. A warm context-free envelope cannot substitute for work under a different caller's pool/token/cache policy. |
| Temporal PAG mediation → window component proofs | Real context passes through compile-time retained window selection, component identification and the distinct path-specific envelope algorithm. Resource/cancellation errors propagate rather than becoming deferred proofs or unidentified mass. Scientific non-identification retains its established disposition. |
| Static graph-class and DAG posterior workers → identification | Context-aware dispatch/configured identification consumes the actual worker context. Scientific non-identification keeps its posterior mass; typed interruption aborts the attempt. Candidate/component ordering is preserved. |
| Static path/distribution/response/counterfactual/attribution → completion | Shared static class helpers and actual samplers receive the caller context, including temporal attribution's default-window sampler. Explicit search limits and completion semantics remain with their scientific owners. |
| Checked Bayesian/static construction → fallback proof replay | Sealed proofs are checked without re-identification. Necessary unsealed replay receives the construction context. Existing premise records or private `CheckedCompileContext` carry this ephemeral dependency; operations do not retain the caller context. Fixed tier-closure/separation checks remain distinct from exact enumeration. |
| Discovered structure → transport over completions → per-member transport | Discovery and structural transport use the caller context. Context-free public wrappers retain their defaults; real facade callers use contextual entry points. |
| Evidence-plan simulation → artifact sealing | Contextual evaluation owns its original prepared laws through sealing. Restricted policies cannot retain those laws in the process memo, and sealing does not re-prepare a different law. Request seed remains authoritative; pool, threads, cancellation and cache policy remain shared. |
| Static response proof → joint response search | The actual context reaches ResponseIdentifier and its generalized joint delegate. In-ceiling admission denial stays typed; an explicit candidate ceiling remains an undecided search. |
| Auto method selection → backdoor/efficient search | Both configured owners receive context; Memory/Cancelled stop the pipeline, while scientific unavailability and declared bounds keep their existing ordered fallback rules. |
| Validation refit → caller error | Resource exhaustion and cancellation retain their typed meanings instead of becoming scientific failure or an unrelated discovery error. The existing non-exhaustive validation error adds its matching resource variant. |

Static and temporal completion consumers share
`antecedent-identify::generalized::check_completion_stop`. `Memory` and
`Cancelled` are non-scientific failures. Caller-declared `Operations`, `Depth`
and completion-retention caps retain their partial/bounded scientific-envelope
semantics. Successful class enumeration remains deterministic, with the same
completion order and weights; passing context introduces no RNG consumption or
scientific identity change. Evidence simulation separately preserves the
request's declared seed while borrowing caller resource ownership.

Context-free public APIs keep their established defaults and signatures.
Context-aware cross-crate entries are intentional additive API changes with
actual facade callers. `TemporalPagCompletionSampler::with_budget`, for example,
uses exactly the default stationary window synthesized by `new`; the old entry
now delegates with its existing default search configuration. Fresh API
comparison must record the precise added surface. No artifact schema, canonical
scientific writer or measured record changes merely to accommodate context.

## Verification and resource limits

Earlier lifecycle/contract/resource tests and the serial-cache production tests
have recorded results in validation. They do not validate source added afterward.
Current new regressions cover warm temporal memo isolation, CPDAG/PAG pulse and
sustained preparation, native PAG mediation windows, default-window sampler
compatibility, and unsealed Bayesian basis/cell-response construction. They
exercise cancellation, tiny budgets, cache-disabled recomputation and unchanged
successful contracts/numerics. Final source gate, lint, native and Python results
remain integration-owned; no reviewer ran competing Cargo validation.

Admission claims remain specific. These fixes remove context/process-retention
escapes and make actual search owners honor their caller. They do not claim
byte-accurate RSS for arbitrary application-provided trait objects. Providers
retain `SignalLimits` obligations. Aggregate compile quotes, live reservations
and observed facts remain different forms of evidence. The standalone
context-free temporal envelope memo remains bounded by entry count and retained
completion count; it is not a claim of exact retained-byte accounting or a
reservation from a later caller's pool. Contextual workflows bypass that memo.
Private numerical cache caps and oversized-entry bypass remain documented with
their own owners. Fresh performance/calibration evidence is still required for
empirical memory or speed claims.
