# Compiled graph-imputation candidate provenance

This candidate composes native chained-equations row imputation, exact DAG
BIC scores over explicitly declared direct-edge support and retained conjugate g-computation. It is a fixed composite, not
an ordinary posterior over a single joint model. The source schema, source
content, declared domains, seeds, each graph mask, retained identification proof
and child program are sealed in the parent identity. Its receipt binds every
completed source, mixture weight, proof and child execution.

The independent enumeration check has known labeled DAG counts of 3, 25 and 543.
The mixture check independently computes the weighted first two moments. The
source reconstruction test mutates encoded input and requires replay refusal.
These are proposed checks and must pass before any provenance review. No
independent scientific review is asserted here.

The registered ignored candidates score the full procedure against a known effect.
The fixed-effect candidate uses independent randomized binary treatment, a continuous
covariate, a Gaussian outcome with treatment effect 0.8, and missing outcomes whose
probability depends only on observed treatment. It is pointwise at that one effect and its
`V2` key cannot match any run of the measured route. It has not been run and creates no
coverage record.

Calibration identity compatibility: the candidate emits the distinct versioned
construction key `GraphImputationCompositeV2` directly from the retained
producer. Existing generic contract classification rejects the reserved composite prefix
before coordinate lookup or legacy normalization, so old artifacts are not
reinterpreted and cannot borrow a Frequentist record. Coverage matching compares the versioned key
exactly; an independent matching test rejects historical inference labels.
A future license must use this producer-specific path, never the generic
unknown-label classifier.

The Python facade holds the same native compiled object through execution and

The ignored calibration target is

Graph scope: the support is declared before any source is scored. Both supports require
the treatment-to-outcome edge and acyclicity, and are enumerated exactly for up to four
variables. Under the root support treatment has no parents, so the empty adjustment set
identifies the same total effect in all atoms (6 graphs on three variables, 100 on four) and
the weights only separate models of the other variables. Under the direct-effect support
treatment may have parents (8 graphs on three variables), the backdoor
adjustment set differs between atoms, and the mixture carries uncertainty about which
variables confound.

Support rule: the declared support is the structurally supported graphs whose
treatment-to-outcome effect has a unique minimal back-door adjustment set
(`unique_minimal_backdoor_adjustment_set`). On four variables some supported graphs have two
minimal sets (for example mask 897 with treatment 0 and outcome 1, where either of two
covariates suffices), which names no single operation; such a graph is excluded rather than
resolved by an arbitrary tie-break. The decision is read from the back-door identifier's own
output, by one derivation that the compiler and the consumer both call, so they keep the same
graphs. The BIC weights and the mixture run over the retained graphs only, the retained masks
and their operations are in the sealed contract, and the number of excluded graphs is sealed in
the contract, the lowered program and the measured scope, and is part of the calibration
functional with the rule label. A consumer given a different retained list or count refuses.
The root support and every three-variable support exclude nothing (6, 100 and 8 retained). Every supported graph is prepared; a missing proof is a typed refusal with
its graph mask and is never dropped or renormalized. Unit tests assert the empty adjustment set
for the root support and differing sets, including the empty one, for the direct-effect support.

Replay: the compiler retains each atom's Bayesian g-computation operation and seals its
identification status and adjustment set, with the data identity and declaration, into one
contract digest that the lowered program commits to. The artifact carries the original table,
the declaration, the lowered program identity and those operations. The consumer in the I/O
layer reconstructs the table and checks its identity, re-derives every atom's identification and
adjustment set from the graph, refuses unless each equals the compiler's retained operation,
and then executes the single native pipeline under the carried program identity. The lowered
program identity itself is carried, not recomputed, by the consumer: it is constrained by the
separately retained expectation and by the contract it commits to. The point, the replayed
artifact and the measured interval share that one implementation.

Licensing: the measured route is `graph_imputation_interval`. It reports the
`GraphImputationCompositeV3` prior-predictive coordinate, whose functional names the support,
variable count, graph count, declared domains, imputation count, sweeps, draws and prior scale,
with the row count in the scope. Seeds are not part of it, since they do not change the
procedure. A record measured over a grid of variable counts and sample sizes therefore covers
executions inside it, and the route refuses with the ordinary no-attesting-record refusal where
none does. No refusal is hard-coded and no record is created here.

A distinct V3 prior-predictive candidate draws the treatment effect once per replicate from
Uniform(-1,1), then generates a binary treatment that is randomized or driven by the
covariates, standard-normal covariates and standard-normal outcome noise. Outcome observation
probability is 0.9 for control and 0.7 for treatment. It evaluates the known sampled effect
through the same native procedure on a grid of cells: three or four variables, randomized or
confounded treatment, and the standard sample-size grid. The exact prior family and the
declaration enter the producer-derived basis. Every failed original-data replicate refuses the
candidate rather than conditioning the coverage calculation on success. Any resulting coverage
describes this prior-predictive distribution, not pointwise or uniform coverage. These
candidates are registered but have not been run, reviewed, attested, or licensed.
