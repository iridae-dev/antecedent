# Typed mechanism shift

Oracle kind: `closed_form` against an independent numpy/scipy target-sample fit. `reference.py` generates a source and a target sample (3000 rows each) in which the income and price mechanisms are invariant and six outcome mechanisms shift to a quadratic price effect: Gaussian (demand), Poisson (orders), Bernoulli (buys), gamma (spend), log-normal (basket) and heteroscedastic Gaussian (noise_h). It fits each outcome on the *target* sample (numpy least squares, or scipy BFGS polished by a root solve of the score equations) and evaluates `E[outcome | do(price = p)]` at p = 0, 1, 2 by Gauss-Hermite quadrature over the source-fitted income law, which is the carried invariant mechanism. It also records the closed-form truth of the data-generating process, a finite-difference delta-method standard error for each response (fit covariance plus the income mean and log-sd), and the Wald consistency statistics of the invariant price and income mechanisms (and of a deliberately shifted price mechanism, `price_shifted`, that a wrongly declared invariance must be flagged on).

`data.json` holds the samples, rounded to nine decimals; every number in `expected.json` is computed from the rounded samples. Regenerate with `python3 reference.py` (numpy and scipy only).

Tests: `cargo test -p antecedent-model --test typed_mechanism_transport`, `cargo test -p antecedent --test suite_09`, and `cd python && uv run pytest tests/test_typed_mechanism_transport.py`. The Rust route fits the same samples itself; the tests compare its transported response with the reference within the Monte Carlo error and with the truth within the delta-method band, its standard error with the reference's, and refuse a shifted mechanism without target evidence, a rejected declared invariance, fits on another design and unknown parameter dependence. The Monte Carlo error is numerical approximation and the fit variance is statistical; neither contains the transport assumption, and no interval is claimed.
